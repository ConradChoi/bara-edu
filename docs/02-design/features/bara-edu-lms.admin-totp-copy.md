# 관리자 2단계 인증(인증 앱) — 최종 문구 (카피 문서)

- 작성일: 2026-11-26
- 작성: ux-writer
- 근거: `bara-edu-lms.admin-totp.md`의 3장(화면), 4.8(메일), 5장(엣지케이스)과 "대표 결정"(Q1~Q6 모두 추천안). 그 문서의 문구 초안을 이 문서가 대체한다. 결정과 다른 곳은 없다.
- 갱신(2026-11-26, service-planner): 10장 확인 사항의 결정(기획서 1.3 D1~D13)과 privacy-security-officer 설계 점검(I-1~I-8)으로 바뀐 문구를 반영했다. 새로 더한 슬롯: MFA-LOGIN-ERR-LOCKED-DAILY, MFA-RESET-BTN-TICKET, MFA-RESET-ERR-LOCKED-DAILY, MFA-RC-PRINT-ALT, MFA-BANNER-MODE-OFF, MFA-BANNER-MODE-OPTIONAL, MFA-CHANGE-*, MFA-SEC-ALREADY-NOTME, MFA-EVENT-*, MFA-MAIL-LOCKED-DAILY-*, MFA-MAIL-ALERT-*(7.6). 뺀 슬롯: MFA-RC-DOWNLOAD, MFA-RC-DOWNLOADED, MFA-LOGIN-ERR-USED-FALLBACK, MFA-MAIL-RCNEW-*(보내지 않음). 새 슬롯 문구는 ux-writer가 말투만 한 번 더 검수한다(뜻은 바꾸지 않는다).
- 말투: 쉬운 `~해요`체. "해 주세요"처럼 띄어 쓴다. 이모지·느낌표 없음. 사용자를 탓하지 않는다. 한 문장에 할 일 하나. 오류에는 "무엇이 안 됐는지 + 다음에 할 일"을 넣는다.
- 범위: 문구만. 코드는 바꾸지 않았다. `{ }`는 화면이나 메일이 채우는 값이다.
- 전화번호와 운영시간은 하드코딩하지 않는다. 메일은 `api/src/mail/support.ts`의 `SUPPORT_PHONE`·`SUPPORT_HOURS`를 템플릿이 자동으로 붙인다(문구 안에 넣지 않는다). 관리자 화면은 기획서 3장 공통 규칙대로 연락처를 적지 않고 "다른 관리자 또는 개발 담당"으로 안내한다.
- 슬롯 ID는 `MFA-` 접두어를 쓴다. 문구를 바꿔도 ID는 유지한다. 기획서에 없는 제안은 **제안**으로 표시한다.
- 어려운 말 풀이: "OTP", "TOTP", "시크릿", "토큰", "인증기"는 화면과 메일에 쓰지 않는다. "QR"은 그림 이름이라 쓰되 "네모난 그림(QR 코드)"으로 처음에 풀어 쓴다.

## 0. 용어

| 용어 | 뜻을 풀어 쓴 말 | 쓰지 않는 말 |
|---|---|---|
| 2단계 인증 | 로그인할 때 비밀번호와 함께 한 번 더 확인하는 것 | OTP, MFA, 이중 인증, 2차 인증 |
| 인증 앱 | 휴대폰에 설치하는 무료 앱. 30초마다 바뀌는 6자리 번호를 보여 줘요 | 인증기, OTP 앱, 인증 프로그램 |
| 6자리 번호 | 인증 앱 화면에 보이는 숫자 여섯 개. 30초마다 바뀌어요 | 인증 번호(문자 인증과 헷갈림), OTP 코드 |
| 복구 코드 | 휴대폰을 쓸 수 없을 때 6자리 번호 대신 한 번씩 쓰는 종이용 코드(10개) | 백업 코드, 비상 코드 |
| 등록 코드 | 다시 등록할 때 다른 관리자나 개발 담당이 전화로 불러 주는 숫자 8자리 | 초기화 코드, 인증 티켓 |
| 인증 앱 등록 | 인증 앱에 바라 평생교육원을 추가하는 일 | 연동, 페어링, 바인딩 |
| 2단계 인증 초기화 | 등록을 지워 새로 등록하게 하는 일(다른 관리자가 함) | 해제, 리셋, 비활성화 |

- "인증 번호"는 문자로 받는 번호로 읽힐 수 있어 "6자리 번호"로 통일한다. 이 서비스는 문자 인증을 하지 않는다.
- "2단계 인증 해제"라는 말은 어디에도 쓰지 않는다. 끌 수 없는 기능이라서 해제할 수 있다는 인상을 주지 않는다(기획서 3.5).
- 숫자는 화면에서 "6자리", "10개", "8자리"처럼 아라비아 숫자로 쓴다.

확인 번호 오류

| 슬롯 ID | 상황 | 문구 |
|---|---|---|
| MFA-CONFIRM-ERR-FORMAT | 6자리 숫자가 아님(서버 호출 없음) | 숫자 6자리를 입력해 주세요. |
| MFA-CONFIRM-ERR-WRONG | 틀림(남은 횟수 있음) | 번호가 맞지 않아요. 앱에 '바라 평생교육원'이 추가됐는지 확인하고, 지금 보이는 번호를 입력해 주세요. ({n}번 더 시도할 수 있어요) |
| MFA-CONFIRM-ERR-TIME | 위 문구 아래 도움말 | 계속 맞지 않으면 휴대폰의 날짜와 시간이 '자동'으로 맞춰져 있는지 확인해 주세요. |
| MFA-CONFIRM-ERR-USED | 방금 쓴 번호 | 방금 쓴 번호예요. 인증 앱에 새 번호가 나오면 입력해 주세요. |
| MFA-CONFIRM-ERR-EXPIRED | 5회 실패 또는 10분 경과 | 등록 시간이 지났어요. 그림과 설정 키를 새로 만들어 다시 등록해 주세요. |
| MFA-CONFIRM-REGEN | 위 오류의 버튼 | QR 코드 새로 만들기 |
| MFA-CONFIRM-REGEN-NOTE | 버튼 아래 | 새로 만들면 지금 그림과 설정 키는 쓸 수 없어요. 인증 앱에 이미 추가한 항목은 지워 주세요. |
| MFA-CONFIRM-ERR-401 | 로그인 중 대기표 만료 | 로그인 시간이 지났어요. 처음부터 다시 로그인해 주세요. |
| MFA-CONFIRM-ERR-LOCKED | 계정 한도(429) | 번호를 여러 번 틀려 잠시 막혔어요. {m}분 뒤에 다시 시도해 주세요. |
| MFA-CONFIRM-ERR-UNAVAILABLE | 연결 불가(503) | 지금 연결이 원활하지 않아요. 잠시 후 다시 눌러 주세요. 번호는 바뀌었을 수 있으니 새 번호를 입력해 주세요. |

- MFA-CONFIRM-ERR-USED는 서버가 `code_reused`를 줄 때 쓴다(기획서 1.3 D1). 새 비밀 키를 확인하는 등록 확인 단계에서는 보통 나오지 않고, 인증 앱 바꾸기의 재확인(지금 번호)에서 나온다.
- 오류 뒤 입력칸은 비우고 포커스를 칸으로 옮긴다(기획서 3 공통 규칙). 번호가 30초마다 바뀌기 때문이다.

| 슬롯 ID | 위치 | 문구 |

## 5. 선택 기간 안내 배너 (M6, 유예 기간)

대표 결정 Q3: 배포 후 7일 유예. 이 기간에 한 번도 등록한 적 없는 관리자는 비밀번호만으로 로그인할 수 있고, 아래 배너가 관리자 화면 위에 보인다(기획서 3.7, 7장). 초기화된 관리자는 유예 중에도 등록 코드가 필요하다(보안 점검 I-1).

N 계산(기획서 1.3 D8): `graceUntil`은 ISO 시각(서울 0시로 둔다, 예 `2026-12-03T00:00:00+09:00`). **N = ⌈(graceUntil − 지금) / 24시간⌉.** N ≥ 2 → GRACE-N, N = 1 → GRACE-1, N ≤ 0 → GRACE-0. 시작일 {date}는 `graceUntil`을 서울 기준 날짜로 바꿔 "12월 3일"처럼 쓴다.

| 슬롯 ID | 조건 | 문구 | 버튼 |
|---|---|---|---|
| MFA-BANNER-GRACE-N | N이 2 이상 | {N}일 뒤부터 관리자 로그인에 인증 앱 번호가 필요해요. 지금 등록해 주세요. | 지금 등록하기 |
| MFA-BANNER-GRACE-1 | N = 1 | 내일부터 관리자 로그인에 인증 앱 번호가 필요해요. 지금 등록해 주세요. | 지금 등록하기 |
| MFA-BANNER-GRACE-0 | N ≤ 0(시작 시각이 지났지만 아직 강제 전) | 오늘부터 관리자 로그인에 인증 앱 번호가 필요해요. 지금 등록하지 않으면 다음 로그인 때 등록 코드가 필요해요. | 지금 등록하기 |
| MFA-BANNER-GRACE-DATE | 위 문구 아래 작은 글씨 | {date}부터 필수예요. | — |
| MFA-BANNER-GRACE-SR | 스크린리더 | 2단계 인증 안내. {위 문구} | — |
| MFA-BANNER-GRACE-LATER | 보조 | 나중에 | — |

- "N일 뒤부터 필수예요"는 요청 문구를 살려 날짜 줄(MFA-BANNER-GRACE-DATE)에 썼다. 본문은 "무엇이 필요한지"를 같이 적어, 인증 앱을 모르는 관리자도 이해하게 했다.
- [나중에]는 이 화면에서만 배너를 접는다. 다음에 화면을 열면 다시 보인다(등록할 때까지). 닫기를 영구로 하지 않는다.

## 6. 자동 로그아웃 안내

대표 결정 Q2: 관리자 세션은 최대 12시간, 1시간 동안 쓰지 않으면 자동 로그아웃(기획서 2.3, 5.4). 이유는 구분해 보여 준다(기획서 1.3 D3, 4.9): 로그인 화면 주소의 `ended=max`면 MFA-SESSION-MAX, `ended=idle`이면 MFA-SESSION-IDLE. `ended`가 없으면 기존 "세션이 만료되었어요" 배너를 그대로 쓴다(MFA-SESSION-GENERIC은 기존 배너를 바꿀 때를 위해 남겨 둔다. 기존 배너 문구 변경은 후속).

| 슬롯 ID | 상황 | 위치 | 문구 |
|---|---|---|---|
| MFA-SESSION-MAX | 로그인한 지 12시간이 지남 | 로그인 화면 상단 배너 | 로그인한 지 12시간이 지나서 로그아웃했어요. 다시 로그인해 주세요. |
| MFA-SESSION-IDLE | 1시간 동안 쓰지 않음 | 로그인 화면 상단 배너 | 1시간 동안 사용하지 않아서 로그아웃했어요. 다시 로그인해 주세요. |
| MFA-SESSION-GENERIC | 이유를 모를 때(기본, 기존 배너와 같은 뜻) | 로그인 화면 상단 배너 | 로그인 시간이 지나서 로그아웃했어요. 다시 로그인해 주세요. |
| MFA-SESSION-WHY | 위 배너 아래 작은 글씨(관리자 화면에서 왔을 때만) | 배너 | 관리자 계정은 개인정보를 지키려고 로그인 시간을 짧게 두었어요. |
| MFA-SESSION-NOTE | 이어서 하던 일 | 배너 | 다시 로그인하면 하던 화면으로 돌아와요. 입력하던 내용은 저장되지 않았을 수 있어요. |
| MFA-SESSION-SOON | 로그아웃 10분 전(12시간 최대 시간 기준)부터 상단 알림. 2026-11-27 구현 | 관리자 화면 상단 알림(2단계 인증 배너 위, warning, role=status, 닫기 없음) | 약 10분 뒤에 로그아웃돼요. 하던 일을 저장해 주세요. |

- MFA-SESSION-NOTE의 두 번째 문장은 폼 입력이 날아갈 수 있다는 사실을 알린다. 사실이 아닌 경우(입력 보존 구현 시)에는 빼고 첫 문장만 쓴다.
- 기존 만료 배너 문구와 어긋나지 않게 "로그아웃했어요"를 같은 기본으로 썼다. 기존 배너는 "세션이 만료되었어요"인데, "세션"은 어려운 말이라 이 기능의 배너는 "로그인 시간이 지나서"로 풀었다. 기존 배너 변경은 이번 범위 밖(후속).
- MFA-SESSION-SOON(2026-11-27 구현): 관리자 레이아웃이 `mfa/status`의 `sessionExpiresAt`(로그인 + 12시간, 30일 만료보다 늦지 않음)에서 서버 시계로 남은 시간을 재어 넘기고, 화면이 받은 순간 기준 마감 시각을 고정해 30초마다·탭이 다시 보일 때·창에 돌아올 때 비교한다(절전·뒤 탭에서 타이머가 밀리는 것 보정, QA I-1). 처음 제안은 "화면을 새로 열 때만"이었으나 관리자 레이아웃은 화면 안 이동 때 다시 그려지지 않아 거의 보이지 않으므로 타이머로 바꿨다(포커스 이동·소리 없음). 1시간 미사용(idle) 로그아웃은 미리 알리지 않는다(사용하면 늘어나므로). 상태 조회 실패·옛 API면 알림 없음.

## 7. 알림 메일

### 7.0 필요 여부

- 기획서 4.8의 메일: 본인용 4종 `mfa_enrolled`, `mfa_reset`, `mfa_recovery_used`, `mfa_locked`, 재설정 완료 메일의 한 줄, 그리고 다른 관리자·운영 주소용 `admin_security_alert`(7.6, 보안 점검 I-6).
- **확정**: 복구 코드를 새로 받았을 때(`복구코드재발급`) 메일은 보내지 않는다(기획서 1.3 D7). 본인이 방금 한 일이고 이미 로그인한 세션에서만 가능하며, 메일이 많아지면 중요한 메일(초기화·복구 코드 로그인)이 묻힌다. 관리자 대시보드의 보안 이벤트 카드(9.1)로 확인한다.
- 구조는 `api/src/mail/ses.ts`의 `Template`(intro → after → closing)을 그대로 쓴다. 인사("안녕하세요. 바라 평생교육원이에요.")·문의처(`SUPPORT_PHONE`, `SUPPORT_HOURS`, 관리자 메일은 `ADMIN_CONTACT_PHONE`이 있으면 아래 관리자 전용 연락처로 대체)·서명은 템플릿이 자동으로 붙인다. 모든 메일에 링크를 넣지 않는다. 6자리 번호·복구 코드·등록 코드·비밀 키는 메일에 적지 않는다. `{at}`는 `kstStamp` 형식(예: 2026년 11월 26일 오후 2시 12분)이다.
- 받는 사람 호칭은 기존 메일처럼 "회원님"이 아니라 관리자 대상이라 "관리자님"으로 하지 않고, 호칭 없이 쓴다. 관리자 메일은 회원 메일과 구분되게 문장을 "~의"로 시작하지 않고 "계정"을 주어로 쓴다.
- 메일은 진짜 주인이 나중에 알아차리게 하려는 것이다. 메일함이 남에게 있으면 그 사람도 읽으므로, 같은 사건을 다른 관리자·운영 주소에도 보낸다(7.6). 본인 메일의 방법 안내는 가장 짧게 쓴다.
- **문의처 블록(확정, 기획서 1.3 D4. 2026-11-27부터 `ADMIN_CONTACT_PHONE`이 있으면 관리자 메일은 아래 항목으로 대체)**: 관리자 메일도 **공통 문의처 블록(`SUPPORT_PHONE`·`SUPPORT_HOURS`)을 그대로** 쓴다. 본문에 "다른 관리자 또는 개발 담당"에게 먼저 알리라고 쓴다. 관리자 전용 연락처가 따로 생기면 그때 관리자 메일만 바꾼다 → 2026-11-27 반영(바로 아래 항목, `ADMIN_CONTACT_PHONE`이 있으면 관리자 메일만 예외).
- **관리자 전용 연락처(2026-11-27 대표 결정, 위 후속 과제 반영)**: 서버 설정 `ADMIN_CONTACT_PHONE`(대표 휴대폰, 값은 문서·코드에 적지 않는다 — 저장소가 공개라서)이 있으면 관리자에게 가는 메일의 문의처 블록만 아래로 바꾼다. 없으면 공통 블록 그대로(지금과 같음).
  - 대상 메일: `mfa_enrolled`, `mfa_reset`, `mfa_recovery_used`, `mfa_locked`, `admin_security_alert`, 관리자 계정의 `password_changed`(관리자 줄이 붙는 경우). 회원 메일은 그대로.
  - MFA-MAIL-ADMIN-CONTACT: `관리자 문의(개발 담당) 전화: {phone}` 한 줄. 운영시간 줄은 붙이지 않는다(운영시간은 회원 문의 기준이라서). "언제든 연락" 같은 약속 문구는 넣지 않는다.
  - 형식: `010-1234-5678`처럼 하이픈이 있는 국내 번호(`0`으로 시작, 2~3·3~4·4자리). 형식이 틀리면 API·CLI가 시작을 거절한다(오타가 메일에 나가지 않게).
  - 받는 곳: `admin_security_alert`는 `ADMIN_SECURITY_ALERT_TO`(관리자 계정이 아닐 수 있는 운영 주소)에도 가므로 이 번호도 그곳에 간다. 지금 번호는 공개 문의처와 같아 문제없고, 나중에 공개하지 않는 번호로 바꾸면 이 점을 다시 본다.
  - 시작 거절 판단(QA Important 2, 2026-11-27): API와 CLI는 같은 `api.env`를 읽으므로 API가 정상으로 켜져 있으면 CLI도 켜진다. 값을 넣거나 바꾼 뒤에는 바로 API 재시작·healthz와 CLI `mfa-report`로 둘 다 켜지는지 확인한다(틀리면 백업으로 되돌린다). 복구 도구(CLI)가 문의처 오타로 막히는 일은 이 확인으로 막는다.
  - 전화 요청 확인(개인정보 점검 권고 1, 2026-11-27): 이 번호로 "관리자인데 등록 코드·잠금 해제가 필요하다"는 전화가 오면 바로 처리하지 않는다. 전화를 끊고 그 관리자의 가입 정보에 있는 휴대전화로 다시 걸어 본인인지 확인한 뒤 CLI를 실행한다(메일함을 가진 사람이 관리자인 척할 수 있으므로). 값을 공개하지 않는 번호로 바꾸면 개인정보 점검을 다시 받는다.

### 7.1 `mfa_enrolled` 2단계 인증이 등록됐어요

받는 사람: 등록한 관리자의 가입 이메일. 언제: 등록 확정 직후.

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| MFA-MAIL-ENROLLED-SUBJECT | 제목 | [바라 평생교육원] 2단계 인증이 등록됐어요 |
| MFA-MAIL-ENROLLED-INTRO-1 | `intro` 1 | 관리자 계정에 2단계 인증이 등록됐어요. |
| MFA-MAIL-ENROLLED-INTRO-2 | `intro` 2 | 등록 시각: {at} |
| MFA-MAIL-ENROLLED-INTRO-3 | `intro` 3 | 앞으로 로그인할 때 비밀번호와 함께 인증 앱의 6자리 번호가 필요해요. |
| MFA-MAIL-ENROLLED-INTRO-4 | `intro` 4 | 직접 등록한 것이 맞다면 따로 하실 일은 없어요. |
| MFA-MAIL-ENROLLED-AFTER | `after` | 본인이 등록하지 않았다면 바로 다른 관리자 또는 개발 담당에게 전화로 알려 주세요. |

- 기기를 바꾸는 등록(입구 C)에도 같은 메일을 쓴다. "인증 앱을 바꿔 등록했다면"을 구분하지는 않는다. 본인이 한 일이면 위 문구가 모두 맞다.

### 7.2 `mfa_reset` 2단계 인증이 초기화됐어요

받는 사람: 초기화된 관리자의 가입 이메일. 언제: 다른 관리자 또는 개발 담당이 초기화한 직후. 처리한 사람 이름은 넣지 않는다(기획서 2.7.2). 등록 코드는 넣지 않는다.

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| MFA-MAIL-RESET-SUBJECT | 제목 | [바라 평생교육원] 2단계 인증이 초기화됐어요 |
| MFA-MAIL-RESET-INTRO-1 | `intro` 1 | 관리자 계정의 2단계 인증이 초기화됐어요. |
| MFA-MAIL-RESET-INTRO-2 | `intro` 2 | 초기화 시각: {at} |
| MFA-MAIL-RESET-INTRO-3 | `intro` 3 | 다른 관리자가 초기화했어요. 모든 기기에서 로그아웃됐어요. |
| MFA-MAIL-RESET-INTRO-4 | `intro` 4 | 다음에 로그인할 때 인증 앱을 새로 등록해야 해요. 이때 등록 코드가 필요해요. 등록 코드는 전화로만 알려 드려요. |
| MFA-MAIL-RESET-INTRO-5 | `intro` 5 | 직접 요청한 것이 맞다면 따로 하실 일은 없어요. |
| MFA-MAIL-RESET-AFTER | `after` | 요청하지 않았다면 바로 다른 관리자 또는 개발 담당에게 전화로 알려 주세요. |
| MFA-MAIL-RESET-CLOSING | `closing` | 이 메일로는 2단계 인증을 초기화하거나 등록 코드를 받을 수 없어요. |

- "다른 관리자가 초기화했어요"는 DB 직접 작업(개발 담당)에도 쓰는 문구다. 사람을 특정하지 않으려고 이 말로 통일했다. 개발 담당이 한 경우에 틀리지 않도록, 개발 담당이 초기화한 경우에는 "관리자 또는 개발 담당이"를 쓸 수 있다(MFA-MAIL-RESET-INTRO-3-DB, **제안**: 관리자 또는 개발 담당이 초기화했어요. 모든 기기에서 로그아웃됐어요.). API가 처리 주체를 알려 줄 수 있으면 분기하고, 아니면 INTRO-3 하나만 쓴다.
- MFA-MAIL-RESET-CLOSING은 메일 속 가짜 안내(등록 코드를 메일로 받는다는 사기)를 막는 문장이다.

### 7.3 `mfa_recovery_used` 복구 코드로 로그인했어요

받는 사람: 복구 코드를 쓴 관리자의 가입 이메일. 언제: 복구 코드로 세션이 만들어진 직후.

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| MFA-MAIL-RECOVERY-SUBJECT | 제목 | [바라 평생교육원] 복구 코드로 로그인했어요 |
| MFA-MAIL-RECOVERY-INTRO-1 | `intro` 1 | 관리자 계정에 복구 코드로 로그인한 기록이 있어요. |
| MFA-MAIL-RECOVERY-INTRO-2 | `intro` 2 | 로그인 시각: {at} |
| MFA-MAIL-RECOVERY-INTRO-3 | `intro` 3 | 남은 복구 코드: {n}개 |
| MFA-MAIL-RECOVERY-INTRO-4 | `intro` 4 | 휴대폰을 쓸 수 없어서 직접 로그인한 것이 맞다면 따로 하실 일은 없어요. 다시 쓸 수 있게 되면 인증 앱을 새로 등록해 주세요. |
| MFA-MAIL-RECOVERY-AFTER | `after` | 본인이 로그인하지 않았다면 바로 다른 관리자 또는 개발 담당에게 전화로 알려 주세요. |

- 남은 코드가 0개일 때는 INTRO-3을 "남은 복구 코드: 없음"으로 쓴다(MFA-MAIL-RECOVERY-INTRO-3-ZERO).
- 복구 코드를 쓴 사람은 휴대폰이 없는 상태이므로 "인증 앱을 새로 등록해 주세요" 안내를 한 번 더 둔다. 메일 안에 링크로 안내하지 않고, 로그인한 화면의 배너(2.4)로 이어진다.

### 7.4 `mfa_locked` 인증 앱 번호가 여러 번 틀렸어요

받는 사람: 잠긴 계정의 가입 이메일(다른 관리자·운영 주소는 7.6). 언제: 계정당 한도(15분 10회 또는 24시간 30회)에 걸린 순간. 계정당 1시간에 1통(기획서 2.9, 2.13). **링크와 주소를 넣지 않고 글로만 안내한다**(기획서 1.3 D5).

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| MFA-MAIL-LOCKED-SUBJECT | 제목 | [바라 평생교육원] 인증 앱 번호가 여러 번 틀렸어요 |
| MFA-MAIL-LOCKED-INTRO-1 | `intro` 1 | 관리자 계정에 비밀번호는 맞게 입력됐지만, 인증 앱 번호가 여러 번 틀렸어요. |
| MFA-MAIL-LOCKED-INTRO-2 | `intro` 2 | 확인 시각: {at} |
| MFA-MAIL-LOCKED-INTRO-3 | `intro` 3 | 안전을 위해 {m}분 동안 이 계정의 번호 입력을 막았어요. |
| MFA-MAIL-LOCKED-INTRO-4 | `intro` 4 | 직접 입력하다 틀린 것이라면 {m}분 뒤에 다시 시도해 주세요. 따로 하실 일은 없어요. |
| MFA-MAIL-LOCKED-AFTER-1 | `after` 1 | 본인이 시도한 것이 아니라면 비밀번호를 새로 정해 주세요. 로그인 화면의 [비밀번호를 잊으셨나요?]에서 할 수 있어요. |
| MFA-MAIL-LOCKED-AFTER-2 | `after` 2 | 이런 메일이 계속 오면 다른 관리자 또는 개발 담당에게 전화로 알려 주세요. |

24시간 한도일 때는 INTRO-3·INTRO-4 대신 아래를 쓴다(보안 점검 I-7).

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| MFA-MAIL-LOCKED-DAILY-INTRO-3 | `intro` 3 | 하루 동안 번호가 너무 많이 틀려서, 안전을 위해 24시간 동안 이 계정의 번호 입력을 막았어요. |
| MFA-MAIL-LOCKED-DAILY-INTRO-4 | `intro` 4 | 직접 입력하다 틀린 것이라면 다른 관리자 또는 개발 담당에게 연락해 주세요. 개발 담당이 잠금을 풀 수 있어요. |

- 주소(`/forgot-password`)는 적지 않고 화면의 버튼 이름으로만 안내한다(확정, 기획서 1.3 D5).
- "비밀번호는 맞게 입력됐지만"은 기획서 초안("비밀번호는 맞았지만")에서 가져왔다. 메일함을 가진 사람이 비밀번호까지 아는 상황이라는 사실을 숨기지 않는다. 다만 "해킹"이라는 말은 쓰지 않는다.
- `{m}`은 15분이다(기획서 2.9). 설정이 바뀌면 이 숫자만 바꾼다.

|---|---|---|
| MFA-MAIL-CHANGED-ADMIN-LINE | `password_changed`의 `intro` 4 아래 한 줄, 관리자 계정일 때만(기획서 2.5 권장) | 2단계 인증은 그대로예요. 로그인할 때 인증 앱의 6자리 번호가 필요해요. |


복구 코드 재발급 메일(MFA-MAIL-RCNEW-*)은 보내지 않기로 확정해 슬롯을 없앴다(7.0).

### 7.6 `admin_security_alert` 다른 관리자·운영 주소용 보안 알림 (보안 점검 I-6)

받는 사람: 사건의 주인이 아닌 활성 관리자 전원과 운영 주소(`ADMIN_SECURITY_ALERT_TO`). 언제: 7.1~7.4의 사건과 관리자 계정의 비밀번호 재설정(기획서 2.13). 한 사람에게 한 통씩. 링크·IP·비밀 값 없음. `{이름}`은 사건 주인의 이름(이메일은 쓰지 않는다).

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| MFA-MAIL-ALERT-SUBJECT | 제목 | [바라 평생교육원] 관리자 {이름}님 계정 보안 알림 |
| MFA-MAIL-ALERT-INTRO-1 | `intro` 1 | 관리자 {이름}님 계정에서 아래 일이 있었어요. |
| MFA-MAIL-ALERT-WHAT | `intro` 2, 사건 줄 | 사건: {사건} |
| MFA-MAIL-ALERT-AT | `intro` 3 | 시각: {at} |
| MFA-MAIL-ALERT-WHY | `intro` 4 | 이 계정의 메일함을 다른 사람이 열 수도 있어서, 다른 관리자에게도 같은 내용을 알려 드려요. |
| MFA-MAIL-ALERT-AFTER-1 | `after` 1 | {이름}님에게 전화로 직접 한 일이 맞는지 확인해 주세요. 메일이나 메신저로 묻지 마세요. |
| MFA-MAIL-ALERT-AFTER-2 | `after` 2 | 본인이 한 일이 아니라면 관리자 화면에서 {이름}님의 2단계 인증을 초기화하고, 개발 담당에게 알려 주세요. |
| MFA-MAIL-ALERT-CLOSING | `closing` | 자세한 기록은 관리자 화면 첫 페이지의 '최근 보안 이벤트'에서 볼 수 있어요. |

`{사건}` 값

| 사건 키 | 문구 |
|---|---|
| `enrolled` | 2단계 인증을 등록했어요(인증 앱 바꾸기 포함). |
| `reset` | 2단계 인증이 초기화됐어요. |
| `recovery_used` | 복구 코드로 로그인했어요. 남은 복구 코드: {n}개 |
| `locked` | 인증 앱 번호가 여러 번 틀려 15분 동안 막혔어요. |
| `locked_daily` | 인증 앱 번호가 너무 많이 틀려 24시간 동안 막혔어요. |
| `password_reset` | 비밀번호 재설정 메일로 비밀번호를 바꿨어요. |

| `unlocked` | 개발 담당이 서버에서 인증 앱 번호 입력 잠금을 풀었어요. (CLI `mfa-unlock`, 보안 점검 m-3, 2026-11-27. 사건 주인 본인 메일은 없음) |

- 사건 `ticket_issued`·`unlocked`(개발 담당이 서버에서 한 일)는 AFTER-1·2 대신 아래 문구를 쓴다(2026-11-27, TOTP 후속 보안 점검 R-2). "본인이 한 일 확인·초기화" 안내가 맞지 않기 때문이다.
  - MFA-MAIL-ALERT-CLI-AFTER-1: {이름}님이 개발 담당에게 직접 요청한 것이 맞는지 {이름}님에게 전화로 확인해 주세요. 메일이나 메신저로 묻지 마세요.
  - MFA-MAIL-ALERT-CLI-AFTER-2: 요청한 적이 없다면 바로 개발 담당에게 전화로 알려 주세요.
- 받는 사람이 운영 주소(개발 담당)일 때도 같은 문구를 쓴다. AFTER-2의 "관리자 화면에서 초기화"를 할 수 없는 사람이라도 "개발 담당에게 알려 주세요"는 자기 자신이므로 문제가 없다. 문구를 나누지 않는다.
- `reset`이 처리한 관리자 자신에게도 가는 것은 의도다(자기가 한 일의 확인).

## 8. 인쇄용 복구 코드 안내지

| 슬롯 ID | 위치 | 문구 |

| MFA-PRINT-TITLE | 제목 | 바라 평생교육원 관리자 복구 코드 |

| MFA-PRINT-LIST-HEAD | 목록 제목 | 복구 코드 (10개, 한 번씩만 쓸 수 있어요) |
| MFA-PRINT-ROW | 목록 줄 | {번호}. {ABCDE-FGHJK}   쓴 날: ________ |

| MFA-PRINT-HOW-4 | 순서 4 | 쓴 코드는 오른쪽 '쓴 날' 칸에 날짜를 적어 두세요. 한 번 쓴 코드는 다시 쓸 수 없어요. |

| MFA-PRINT-LOST-1 | 안내 | 로그인할 수 있다면 [내 보안 설정]에서 새 복구 코드를 받아 주세요. 로그인할 수 없다면 다른 관리자 또는 개발 담당에게 전화로 2단계 인증 초기화를 요청해 주세요. |

- "두 장 인쇄해"는 대표 결정 Q4(두 곳 보관)를 쉬운 행동으로 풀었다.
- "쓴 날" 칸은 관리자가 몇 개 남았는지 알도록 하는 장치다. 화면의 남은 개수와 종이를 맞춰 볼 수 있다.
