# 관리자 2단계 인증(인증 앱) — 최종 문구 (카피 문서)

- 작성일: 2026-11-26
- 작성: ux-writer
- 근거: `bara-edu-lms.admin-totp.md`의 3장(화면), 4.7(메일), 5장(엣지케이스)과 "대표 결정"(Q1~Q6 모두 추천안). 그 문서의 문구 초안을 이 문서가 대체한다. 결정과 다른 곳은 없다. 기획서는 디자이너가 수정 중이라 이 문서는 절 번호로만 가리킨다.
- 말투: 쉬운 `~해요`체. "해 주세요"처럼 띄어 쓴다. 이모지·느낌표 없음. 사용자를 탓하지 않는다. 한 문장에 할 일 하나. 오류에는 "무엇이 안 됐는지 + 다음에 할 일"을 넣는다.
- 범위: 문구만. 코드는 바꾸지 않았다. `{ }`는 화면이나 메일이 채우는 값이다.
- 전화번호와 운영시간은 하드코딩하지 않는다. 메일은 `api/src/mail/support.ts`의 `SUPPORT_PHONE`·`SUPPORT_HOURS`를 템플릿이 자동으로 붙인다(문구 안에 넣지 않는다). 관리자 화면은 기획서 3장 공통 규칙대로 연락처를 적지 않고 "다른 관리자 또는 개발 담당"으로 안내한다.
- 슬롯 ID는 `MFA-` 접두어를 쓴다. 문구를 바꿔도 ID는 유지한다. 기획서에 없는 제안은 **제안**으로 표시한다.
- 어려운 말 풀이: "OTP", "TOTP", "시크릿", "토큰", "인증기"는 화면과 메일에 쓰지 않는다. "QR"은 그림 이름이라 쓰되 "네모난 그림(QR 코드)"으로 처음에 풀어 쓴다.

## 0. 용어

| 용어 | 뜻을 풀어 쓴 말 | 쓰지 않는 말 |
|---|---|---|
| 2단계 인증 | 로그인할 때 비밀번호와 함께 한 번 더 확인하는 것 | OTP, MFA, 이중 인증, 2차 인증 |
| 인증 앱 | 휴대폰에 설치하는 무료 앱. 30초마다 바뀌는 6자리 번호를 보여 줘요 | 인증기, OTP 앱, 인증 프로그램 |
| 6자리 번호 | 인증 앱 화면에 보이는 숫자 여섯 개. 30초마다 바뀌어요 | 인증 번호(문자 인증과 헷갈림), OTP 코드 |
| 복구 코드 | 휴대폰을 쓸 수 없을 때 6자리 번호 대신 한 번씩 쓰는 종이용 코드(10개) | 백업 코드, 비상 코드 |
| 등록 코드 | 다시 등록할 때 다른 관리자나 개발 담당이 전화로 불러 주는 숫자 8자리 | 초기화 코드, 인증 티켓 |
| 인증 앱 등록 | 인증 앱에 바라 평생교육원을 추가하는 일 | 연동, 페어링, 바인딩 |
| 2단계 인증 초기화 | 등록을 지워 새로 등록하게 하는 일(다른 관리자가 함) | 해제, 리셋, 비활성화 |

- "인증 번호"는 문자로 받는 번호로 읽힐 수 있어 "6자리 번호"로 통일한다. 이 서비스는 문자 인증을 하지 않는다.
- "2단계 인증 해제"라는 말은 어디에도 쓰지 않는다. 끌 수 없는 기능이라서 해제할 수 있다는 인상을 주지 않는다(기획서 3.5).
- 숫자는 화면에서 "6자리", "10개", "8자리"처럼 아라비아 숫자로 쓴다.

## 1. 등록 화면 (M3, M4 공통)

위치: `/sign-in/otp-setup`, `/admin/security`의 등록 단계(기획서 3.4). 진행 표시와 단계 이름은 입구에 따라 "등록 코드" 단계가 없을 수 있다.

### 1.1 진행 표시

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| MFA-SETUP-STEPS-A | 진행 표시(등록 코드 있음) | 1. 앱 준비 / 2. 등록 코드 / 3. 인증 앱 등록 / 4. 복구 코드 보관 |
| MFA-SETUP-STEPS-B | 진행 표시(등록 코드 없음) | 1. 앱 준비 / 2. 인증 앱 등록 / 3. 복구 코드 보관 |

| MFA-SETUP-BACKUP-HELP | 주의 상자 아래 | 백업을 켜지 않아도 괜찮아요. 켜는 경우에만 지켜 주세요. |

- "백업(동기화)"은 괄호로 풀었다. 앱 안에서는 "클라우드 백업", "동기화"로 보일 수 있다.
- MFA-SETUP-BACKUP-BODY의 "다른 계정"은 "예: 개인 구글 계정이 아니라 회사 계정" 같은 예를 달지 않는다. 계정 종류가 관리자마다 달라 오히려 헷갈린다.

| MFA-CONFIRM-ERR-USED | 방금 쓴 번호 | 방금 쓴 번호예요. 인증 앱에 새 번호가 나오면 입력해 주세요. |
| MFA-CONFIRM-ERR-EXPIRED | 5회 실패 또는 10분 경과 | 등록 시간이 지났어요. 그림과 설정 키를 새로 만들어 다시 등록해 주세요. |
| MFA-CONFIRM-REGEN | 위 오류의 버튼 | QR 코드 새로 만들기 |
| MFA-CONFIRM-REGEN-NOTE | 버튼 아래 | 새로 만들면 지금 그림과 설정 키는 쓸 수 없어요. 인증 앱에 이미 추가한 항목은 지워 주세요. |
| MFA-CONFIRM-ERR-401 | 로그인 중 대기표 만료 | 로그인 시간이 지났어요. 처음부터 다시 로그인해 주세요. |
| MFA-CONFIRM-ERR-LOCKED | 계정 한도(429) | 번호를 여러 번 틀려 잠시 막혔어요. {m}분 뒤에 다시 시도해 주세요. |
| MFA-CONFIRM-ERR-UNAVAILABLE | 연결 불가(503) | 지금 연결이 원활하지 않아요. 잠시 후 다시 눌러 주세요. 번호는 바뀌었을 수 있으니 새 번호를 입력해 주세요. |

- MFA-CONFIRM-ERR-USED는 기획서 2.8의 화면 문구를 그대로 옮겼다. 다만 기획서 3.2·4.2는 재사용을 `wrong_code`와 같은 응답으로 준다고 해서 화면이 구분할 수 없다. 10장 확인 사항 1 참고.
- 오류 뒤 입력칸은 비우고 포커스를 칸으로 옮긴다(기획서 3 공통 규칙). 번호가 30초마다 바뀌기 때문이다.

## 6. 자동 로그아웃 안내

대표 결정 Q2: 관리자 세션은 최대 12시간, 1시간 동안 쓰지 않으면 자동 로그아웃(기획서 2.3, 5.4). 만료된 요청은 로그인 화면으로 가며 기존 "세션이 만료되었어요" 배너를 쓴다. 아래는 이유를 구분해 보여 줄 때의 문구다.

| 슬롯 ID | 상황 | 위치 | 문구 |
|---|---|---|---|
| MFA-SESSION-MAX | 로그인한 지 12시간이 지남 | 로그인 화면 상단 배너 | 로그인한 지 12시간이 지나서 로그아웃했어요. 다시 로그인해 주세요. |
| MFA-SESSION-IDLE | 1시간 동안 쓰지 않음 | 로그인 화면 상단 배너 | 1시간 동안 사용하지 않아서 로그아웃했어요. 다시 로그인해 주세요. |
| MFA-SESSION-GENERIC | 이유를 모를 때(기본, 기존 배너와 같은 뜻) | 로그인 화면 상단 배너 | 로그인 시간이 지나서 로그아웃했어요. 다시 로그인해 주세요. |
| MFA-SESSION-WHY | 위 배너 아래 작은 글씨(관리자 화면에서 왔을 때만) | 배너 | 관리자 계정은 개인정보를 지키려고 로그인 시간을 짧게 두었어요. |
| MFA-SESSION-NOTE | 이어서 하던 일 | 배너 | 다시 로그인하면 하던 화면으로 돌아와요. 입력하던 내용은 저장되지 않았을 수 있어요. |
| MFA-SESSION-SOON | **제안** 로그아웃 10분 전(최대 시간 기준)에 상단 알림, 화면을 새로 열 때만 | 상단 알림 | 약 10분 뒤에 로그아웃돼요. 하던 일을 저장해 주세요. |

- MFA-SESSION-SOON은 기획서에 없다(제안). 쓰지 않아도 기능은 완결된다. 쓰려면 화면이 서버가 내려 주는 만료 시각을 알아야 한다.

## 7. 알림 메일

### 7.0 필요 여부

- 기획서가 메일 4종을 정했다(4.7): `mfa_enrolled`, `mfa_reset`, `mfa_recovery_used`, `mfa_locked`. 아래 문구는 그 4종과, 2.5가 권장한 재설정 완료 메일의 한 줄이다. 모두 기획서에 있는 메일이라 새로 제안하는 메일은 없다.
- **제안**: 복구 코드를 새로 받았을 때(`복구코드재발급`) 메일은 보내지 않는다. 본인이 방금 한 일이고 이미 로그인한 세션에서만 가능하며, 메일이 많아지면 중요한 메일(초기화·복구 코드 로그인)이 묻힌다. 필요하면 7.5의 제안 문구를 쓴다.
- 구조는 `api/src/mail/ses.ts`의 `Template`(intro → after → closing)을 그대로 쓴다. 인사("안녕하세요. 바라 평생교육원이에요.")·문의처(`SUPPORT_PHONE`, `SUPPORT_HOURS`)·서명은 템플릿이 자동으로 붙인다. 모든 메일에 링크를 넣지 않는다. 6자리 번호·복구 코드·등록 코드·비밀 키는 메일에 적지 않는다. `{at}`는 `kstStamp` 형식(예: 2026년 11월 26일 오후 2시 12분)이다.
- 받는 사람 호칭은 기존 메일처럼 "회원님"이 아니라 관리자 대상이라 "관리자님"으로 하지 않고, 호칭 없이 쓴다. 관리자 메일은 회원 메일과 구분되게 문장을 "~의"로 시작하지 않고 "계정"을 주어로 쓴다.
- 메일은 진짜 주인이 나중에 알아차리게 하려는 것이다. 메일함이 남에게 있으면 그 사람도 읽는다는 점을 기획서 4.7이 밝혔다. 그래서 "~하면 된다"는 방법 안내를 가장 짧게 쓴다.
- 문의처 블록이 회원 고객센터 번호라는 점은 10장 확인 사항 4에 적었다. "다른 관리자 또는 개발 담당"에게 먼저 알리라고 본문에 쓰고, 번호는 템플릿이 붙이는 것을 그대로 쓴다.

- 기기를 바꾸는 등록(입구 C)에도 같은 메일을 쓴다. "인증 앱을 바꿔 등록했다면"을 구분하지는 않는다. 본인이 한 일이면 위 문구가 모두 맞다.

### 7.2 `mfa_reset` 2단계 인증이 초기화됐어요

받는 사람: 초기화된 관리자의 가입 이메일. 언제: 다른 관리자 또는 개발 담당이 초기화한 직후. 처리한 사람 이름은 넣지 않는다(기획서 2.7.2). 등록 코드는 넣지 않는다.

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| MFA-MAIL-RESET-SUBJECT | 제목 | [바라 평생교육원] 2단계 인증이 초기화됐어요 |
| MFA-MAIL-RESET-INTRO-1 | `intro` 1 | 관리자 계정의 2단계 인증이 초기화됐어요. |
| MFA-MAIL-RESET-INTRO-2 | `intro` 2 | 초기화 시각: {at} |
| MFA-MAIL-RESET-INTRO-3 | `intro` 3 | 다른 관리자가 초기화했어요. 모든 기기에서 로그아웃됐어요. |
| MFA-MAIL-RESET-INTRO-4 | `intro` 4 | 다음에 로그인할 때 인증 앱을 새로 등록해야 해요. 이때 등록 코드가 필요해요. 등록 코드는 전화로만 알려 드려요. |
| MFA-MAIL-RESET-INTRO-5 | `intro` 5 | 직접 요청한 것이 맞다면 따로 하실 일은 없어요. |
| MFA-MAIL-RESET-AFTER | `after` | 요청하지 않았다면 바로 다른 관리자 또는 개발 담당에게 전화로 알려 주세요. |
| MFA-MAIL-RESET-CLOSING | `closing` | 이 메일로는 2단계 인증을 초기화하거나 등록 코드를 받을 수 없어요. |

- "다른 관리자가 초기화했어요"는 DB 직접 작업(개발 담당)에도 쓰는 문구다. 사람을 특정하지 않으려고 이 말로 통일했다. 개발 담당이 한 경우에 틀리지 않도록, 개발 담당이 초기화한 경우에는 "관리자 또는 개발 담당이"를 쓸 수 있다(MFA-MAIL-RESET-INTRO-3-DB, **제안**: 관리자 또는 개발 담당이 초기화했어요. 모든 기기에서 로그아웃됐어요.). API가 처리 주체를 알려 줄 수 있으면 분기하고, 아니면 INTRO-3 하나만 쓴다.
- MFA-MAIL-RESET-CLOSING은 메일 속 가짜 안내(등록 코드를 메일로 받는다는 사기)를 막는 문장이다.

## 10. 확인이 필요한 것

1. **방금 쓴 번호**: 기획서 2.8은 재사용 시 "방금 쓴 번호예요. 인증 앱에 새 번호가 나오면 입력해 주세요"를 보여 주라고 하지만, 3.2·4.2는 재사용을 `wrong_code`와 같은 응답으로 준다고 한다. 구분 응답(예: `code_used`)이 없으면 화면은 MFA-LOGIN-ERR-USED 대신 MFA-LOGIN-ERR-USED-FALLBACK(WRONG에 덧붙이는 한 줄)을 쓴다. 구분하면 정상 사용자가 두 번 누른 경우에만 알려 줄 수 있지만, 번호를 아는 공격자에게 "방금 쓴 번호"라는 힌트가 되지는 않는지 privacy-security-officer가 판단한다.
2. **초기화 여부 표시**: MFA-REENROLL-TITLE·DESC는 서버가 "초기화된 계정"임을 로그인 응답(`enroll_required`)에 알려 줄 때만 쓴다. 기획서 4.1은 `ticketRequired`만 있다. 알려 주지 않으면 1.2의 제목을 그대로 쓴다(이때 비밀번호가 맞은 사람에게만 보이는 화면이라 열거 위험은 없다).
3. **자동 로그아웃 이유 구분**: 기획서 5.4는 기존 "세션이 만료되었어요" 배너만 정한다. 12시간과 1시간을 구분해 보여 주려면 401 응답이나 리다이렉트 값에 이유(`max`/`idle`)가 필요하다. 구분하지 않으면 MFA-SESSION-GENERIC 하나를 쓴다. 기존 배너의 "세션"이라는 말도 쉬운 말로 바꿀지 결정이 필요하다.
4. **메일의 문의처 블록**: `SUPPORT_PHONE`은 회원용 고객센터 번호다. 관리자가 휴대폰 분실 같은 문제로 이 번호에 전화하면, 고객센터 담당자가 2단계 인증 문제를 아는지 확인이 필요하다. 본문 `after`에 "다른 관리자 또는 개발 담당에게 전화로"라고 적었지만 번호는 템플릿의 하나뿐이다. 관리자 메일 전용 문의처 블록이 필요한지 정해 달라.
5. **`mfa_locked` 메일의 주소 안내**: 기획서 4.7은 `/forgot-password` 주소를 적으라고 했다. 이 문서는 요청대로 링크·주소를 넣지 않고 버튼 이름으로 안내했다. 주소가 꼭 필요하면 `already_registered`의 `forgotLink` 방식(MAIL-REG-AFTER-2)을 따른다.
6. **인쇄 안내지에 이름 인쇄**: MFA-PRINT-WHO에 관리자 이름을 적을지 정해 달라. 이메일은 적지 않는다.
7. **복구 코드 재발급 메일**: 기획서에 없다. 7.0은 보내지 않기를 제안했다. 보내려면 MFA-MAIL-RCNEW-* 문구를 쓰고 `mailer.ts` 템플릿을 하나 더한다.
8. **유예 배너의 N 계산**: 서울 기준 날짜 차이로 센다. `graceUntil`이 날짜인지 시각인지 확인해 N을 정한다.
9. 메일 문구가 확정되면 `api/test/ses.test.ts`의 메일 본문 테스트에 "링크 없음", "6자리 번호·복구 코드·등록 코드가 본문에 없음", "전화·운영시간이 있음"을 넣는다(qa-reviewer).
10. SES 위탁 범위: 보안 알림 4종이 "회원가입 인증·비밀번호 재설정·회원 정보 변경 안내" 범위에 들어가는지는 기획서 6장대로 privacy-security-officer가 확인한다.
