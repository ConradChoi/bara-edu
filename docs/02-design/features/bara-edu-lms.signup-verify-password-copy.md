# 가입 인증 비밀번호 확인 — 최종 문구 (카피 문서)

- 작성일: 2026-11-25
- 작성: ux-writer
- 근거: `bara-edu-lms.signup-verify-password.md`의 "대표 결정 (2026-11-25)" 7건. 그 문서 7장의 초안을 이 문서가 대체한다.
- 말투: 쉬운 `~해요`체. "해 주세요"처럼 띄어 쓴다. 이모지·느낌표 없음. 사용자를 탓하지 않는다. 시니어 학습자 기준으로 짧게 쓴다.
- 범위: 문구만. 코드는 바꾸지 않았다. `{ }`는 화면이 채우는 값이다.
- 전화번호와 운영시간은 하드코딩하지 않는다. 앱은 `siteConfig.phone`·`siteConfig.supportHours`, API 메일은 `api/src/mail/support.ts`의 `SUPPORT_PHONE`·`SUPPORT_HOURS`를 쓴다. 현재 값은 `010-9025-5093`, `평일 10:00~18:00(점심 11:30~13:00 제외)`이다.

## 0. 용어 (이 기능 전용)

| 용어 | 쓰는 곳 | 쓰지 않는 말 |
|---|---|---|
| 가입 마무리 | 링크를 연 뒤 비밀번호를 입력하는 화면 이름, 안내 문장 | 인증 완료, 본인 확인, 2차 인증 |
| 가입 완료하기 | 가입 마무리 화면의 주 버튼 | 확인, 제출, 인증하기 |
| 비밀번호 확인 | 가입 폼의 두 번째 칸 라벨 | 비밀번호 재입력, 비밀번호 체크 |
| 처음부터 다시 가입하기 | 기억나지 않을 때·잠김·만료의 버튼 | 재가입, 가입 초기화 |
| 가입 마무리 전 | 관리자 화면 배지(기존 "미인증") | 미인증, 대기 |

"비밀번호 확인"은 가입 폼의 칸 이름이고, "가입 마무리"의 비밀번호 칸은 그냥 "비밀번호"라고 부른다. 두 화면의 이름이 같으면 헷갈린다.

## 1. 가입 폼 (`/sign-up`, 기존 비밀번호 칸 아래에 추가)

| 위치 | 문구 |
|---|---|
| 새 칸 라벨 | 비밀번호 확인 |
| 도움말(칸 아래, 평소 표시) | 위에 입력한 비밀번호를 한 번 더 입력해 주세요. 다음 단계에서 이 비밀번호가 다시 필요해요. |
| 오류: 비어 있음 | 비밀번호를 한 번 더 입력해 주세요 |
| 오류: 불일치 | 비밀번호가 서로 달라요. 두 칸에 같은 비밀번호를 입력해 주세요. |
| 토글(숨김 상태일 때 글자) | 보기 |
| 토글(보이는 상태일 때 글자) | 숨기기 |
| 토글 스크린리더 라벨 | 비밀번호 보기 / 비밀번호 숨기기 |

- 토글은 두 칸을 함께 바꾼다. 칸마다 따로 두면 시니어가 두 번 눌러야 한다. 비밀번호 칸 오른쪽에 하나만 둬도 되고, 각 칸에 하나씩 두려면 같은 상태로 움직이게 한다.
- 불일치 오류는 칸을 벗어날 때(blur)나 제출할 때 보여 준다. 입력하는 도중에는 띄우지 않는다.
- 기존 오류 문구 "비밀번호는 8자 이상 200자 이하로 입력해 주세요"(`lib/form-messages.ts`)는 그대로 둔다.

도움말 옵션

| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (권장) | 위에 입력한 비밀번호를 한 번 더 입력해 주세요. 다음 단계에서 이 비밀번호가 다시 필요해요. | 이유를 알려 주어 오타를 조심하게 한다. 두 문장이라도 짧다. |
| B | 위와 같은 비밀번호를 입력해 주세요. | 가장 짧다. 이유가 없어 입력 부담만 느낄 수 있다. |
| C | 비밀번호를 잘못 입력하지 않았는지 확인해요. | 목적은 분명하지만 "잘못"이라는 말이 사용자를 의심하는 느낌을 준다. 비권장. |

## 2. 가입 후 안내 화면 (예고를 넣는다)

판단: 넣는다. 이유는 세 가지다.
1. 링크를 열면 비밀번호를 한 번 더 묻는다. 모르고 열면 당황하고, 5회 틀리면 링크가 영구히 잠긴다.
2. 시니어는 메일을 열기 전에 비밀번호를 잊거나 메모하지 않을 수 있다. 이 화면이 "기억해 두세요"를 말할 마지막 기회다.
3. 이 화면은 가입 여부를 숨겨야 해서 "가입이 처음이면"으로 시작하는 한 줄에 합칠 수 있다. 문장이 늘지 않는다.

기존 화면(`signup-enumeration-copy.md` 2장)의 본문 두 번째 줄을 아래로 바꾼다. 첫 줄과 "메일이 안 올 때" 블록은 그대로다.

| 위치 | 문구 |
|---|---|
| 제목 | 메일을 보냈어요 (유지) |
| 본문 1 | `{email}`로 안내 메일을 보냈어요. 메일함을 확인해 주세요. (유지) |
| 본문 2 (변경) | 가입이 처음이면 메일 안의 링크를 열고, 방금 정한 비밀번호를 한 번 더 입력해 주세요. 그러면 가입이 끝나요. |

본문 2 옵션

| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (권장) | 가입이 처음이면 메일 안의 링크를 열고, 방금 정한 비밀번호를 한 번 더 입력해 주세요. 그러면 가입이 끝나요. | 순서(링크, 비밀번호, 끝)가 한 번에 보인다. 가입 여부를 드러내지 않는다. |
| B | 가입이 처음이면 메일 안의 링크를 눌러 가입을 마칠 수 있어요. 이때 방금 정한 비밀번호가 필요해요. | 서비스 정의서 7.3절 초안에 가깝다. "필요해요"는 할 일이 분명하지 않다. |
| C | 메일 속 링크를 열면 비밀번호를 다시 물어요. 방금 정한 비밀번호를 준비해 주세요. | 가장 직접적이다. 기존 회원에게도 같은 화면이 보이므로 사실과 어긋난다. 비권장. |

- "이미"·"다시"는 쓰지 않는다. 가입 여부를 암시한다. 옵션 A의 "한 번 더"는 방금 입력한 비밀번호를 가리키는 말이라 괜찮다.
- 로그인 시 미인증 계정 안내(enumeration 문서 방법 A)에도 한 줄을 더한다: "링크를 열면 가입할 때 정한 비밀번호를 한 번 더 입력해요."
- 환영 배너(`/my?welcome=1`): "다음부터는 이메일과 방금 입력한 비밀번호로 로그인해요."

## 3. 인증 메일 본문 (`api/src/mail/ses.ts`의 `confirm` 템플릿)

현재 `confirm` 템플릿은 인사말, 문단, 링크, 전화·운영시간, 서명 순서로 만든다. 그 구조는 바꾸지 않고 제목과 `intro`만 바꾼다. 링크는 지금처럼 주소 한 줄이므로 "가입 마무리하기"는 링크 이름이 아니라 링크 앞 문장 속에 둔다.

제목
- 현재: [바라 평생교육원] 이메일 인증을 완료해 주세요
- 변경: **[바라 평생교육원] 가입을 마무리해 주세요**
- 이유: 링크를 눌러도 바로 끝나지 않고 비밀번호를 묻기 때문에, "인증을 완료"라는 말은 기대와 다르다.

`intro` (링크 앞 문단)

```
안녕하세요. 바라 평생교육원이에요.

아래 링크를 열고, 가입할 때 정한 비밀번호를 입력해 주세요. 그러면 가입이 끝나요.
링크는 24시간 동안 쓸 수 있어요.

본인이 가입을 요청하지 않았다면 이 메일을 무시해 주세요. 아무것도 바뀌지 않아요.

{가입 마무리 링크}

전화: {SUPPORT_PHONE}
운영시간: {SUPPORT_HOURS}

바라 평생교육원
```

- 위 본문의 "링크 앞 두 문단"이 `intro` 두 항목이다. "아무것도 바뀌지 않아요"는 이미 가입된 계정 안내 메일과 같은 말이라 맞춘다.
- 전화·운영시간·서명은 템플릿이 자동으로 붙이므로 `intro`에 넣지 않는다. 문서에 적은 것은 완성된 모양을 보이기 위해서다.
- 링크가 잘려 열리지 않는 경우(5.9절)를 위해 `after`에 한 줄을 추가하는 안: "링크가 열리지 않으면 주소를 복사해 인터넷 창에 붙여 넣어 주세요." 메일 앱이 링크를 줄바꿈하는 일이 있어 권장한다.
- 비밀번호를 메일에 적지 않는다. 가입 정보나 "이 메일은 이 가입 요청용"이라는 설명도 넣지 않는다(정의서 5.7절 이유).

`intro` 두 항목 옵션

| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (권장) | 아래 링크를 열고, 가입할 때 정한 비밀번호를 입력해 주세요. 그러면 가입이 끝나요. 링크는 24시간 동안 쓸 수 있어요. | 순서와 기한이 한 번에 보인다. |
| B | 아래 링크를 눌러 가입을 마무리해 주세요. 링크를 열면 가입할 때 입력한 비밀번호를 한 번 더 물어요. | 화면 이름과 같은 말을 쓴다. 비밀번호가 필요하다는 점이 뒤에 나와 놓치기 쉽다. |

## 4. "가입 마무리" 화면 (`/auth/confirm?token=`)

### 4.1 ready: 비밀번호 입력

| 위치 | 문구 |
|---|---|
| 제목 | 가입을 마무리해 주세요 |
| 설명 | 가입할 때 정한 비밀번호를 입력하면 가입이 끝나요. |
| 정보: 이메일 | 가입 이메일 `{email}` |
| 정보: 요청 시각 | 가입 요청 `{11월 25일 오후 3시 10분}` |
| 정보: 남은 시간 | `{n}시간 안에 마쳐 주세요` (1시간 미만이면 "1시간 안에 마쳐 주세요") |
| 입력 라벨 | 비밀번호 |
| 입력 보조문 | 가입할 때 정한 비밀번호 |
| 토글 | 보기 / 숨기기 (스크린리더: 비밀번호 보기 / 비밀번호 숨기기) |
| 주 버튼 | 가입 완료하기 |
| 제출 중(버튼) | 확인하고 있어요 |
| 하단 안내 | 본인이 가입을 요청하지 않았다면 이 화면을 닫아 주세요. 아무것도 바뀌지 않아요. |
| 칸 비어 있음 | 비밀번호를 입력해 주세요 |
| 성공 | 별도 화면 없음. `/my?welcome=1`로 이동해 환영 배너 표시: "가입이 끝났어요. 바라 평생교육원에 오신 것을 환영해요." / "다음부터는 이메일과 방금 입력한 비밀번호로 로그인해요." |

- 제출 중 문구를 "확인하는 중이에요"에서 "확인하고 있어요"로 바꾼 이유: 버튼 안에서 짧게 읽히고, 용어집의 "~하는 중" 표현보다 부드럽다. 기존 재전송 "보내는 중이에요"와 같이 쓰려면 정의서 초안의 "확인하는 중이에요"를 유지해도 된다. 둘 중 하나로 화면 전체를 통일한다.
- 성공 환영 문구에 느낌표를 쓰지 않는다.

### 4.2 틀림: 남은 횟수 (1~4번째)

오류는 입력 칸 위에 두고, 칸은 비운다. 보기 상태는 유지한다. 한 번에 한 가지 일만 안내한다.

| 틀린 횟수 | 남은 횟수 | 오류 줄 | 횟수 줄 |
|---|---|---|---|
| 1번째 | 4번 | 비밀번호가 맞지 않아요. | 4번 더 입력해 볼 수 있어요. |
| 2번째 | 3번 | 비밀번호가 맞지 않아요. | 3번 더 입력해 볼 수 있어요. |
| 3번째 | 2번 | 비밀번호가 맞지 않아요. | 2번 더 입력해 볼 수 있어요. |
| 4번째 | 1번 | 비밀번호가 맞지 않아요. | 마지막 1번 남았어요. 천천히 확인해 주세요. |

도움말(1번째부터 항상 오류 아래에 표시)
- 가입할 때 정한 비밀번호가 맞는지 확인해 주세요. 한/영 키와 Caps Lock이 켜져 있는지도 살펴봐 주세요.
- 다른 인증 메일을 받았다면 그 메일의 링크도 열어 보세요.

옵션 (오류 줄)

| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (권장) | 비밀번호가 맞지 않아요. | 사용자를 탓하지 않고 상태만 말한다. |
| B | 비밀번호가 틀렸어요. | 더 직접적이지만 "틀렸다"가 사용자의 잘못처럼 들린다. |
| C | 비밀번호를 다시 확인해 주세요. | 부드럽지만 틀렸다는 사실이 흐려져 횟수가 줄었다는 점이 뒤늦게 느껴진다. |

- 정의서 초안의 "가입할 때 입력한 비밀번호를 다시 확인해 주세요"는 도움말 첫 문장과 겹쳐 하나로 합쳤다.
- 4번째의 "마지막 1번 남았어요"는 불안을 키우지 않도록 "천천히 확인해 주세요"를 붙였다. 경고 색을 쓰되 문구는 차분하게 한다.

### 4.3 3회째부터 "기억나지 않아요" 영역

3번째 불일치부터 자동으로 펼친다. 1~2번째에는 접힌 채 제목만 보인다.

| 위치 | 문구 |
|---|---|
| 접기 제목 | 비밀번호가 기억나지 않아요 |
| 본문 1 | 처음부터 다시 가입하면 새 인증 메일을 보내 드려요. 그 메일에서 새로 정한 비밀번호로 가입을 마칠 수 있어요. |
| 버튼 | 처음부터 다시 가입하기 |
| 본문 2(전화) | 다시 가입이 어려우면 전화로 문의해 주세요. |
| 전화 | 전화 `{siteConfig.phone}` (`tel:` 링크) |
| 운영시간 | 운영시간 `{siteConfig.supportHours}` |

- 버튼은 `/sign-up?email={email}`로 이동한다. 이메일만 채워 주고 이름·연락처·비밀번호는 채우지 않는다.
- 메일이 오지 않을 때의 안내는 가입 직후 화면의 "메일이 안 올 때"가 맡는다. 여기에는 반복하지 않는다.

### 4.4 5회 잠김 (`locked`)

| 위치 | 문구 |
|---|---|
| 제목 | 이 링크는 더 쓸 수 없어요 |
| 설명 | 비밀번호가 5번 맞지 않아서 이 링크를 잠갔어요. 개인정보를 지키기 위한 조치예요. |
| 해결 안내 | 처음부터 다시 가입하면 새 인증 메일을 보내 드려요. |
| 주 버튼 | 처음부터 다시 가입하기 |
| 전화 | 다시 가입이 어려우면 전화로 문의해 주세요. 전화 `{siteConfig.phone}` / 운영시간 `{siteConfig.supportHours}` |

- 잠김 이유에 "계정을 지키기 위해"라고 쓰지 않고 "개인정보를 지키기 위한 조치"로 썼다. 사용자가 벌을 받는 느낌을 줄인다. 더 짧게 하려면 이 문장을 뺀다.
- 잠금은 시간이 지나도 풀리지 않는다. "잠시 후 다시"라는 표현은 쓰지 않는다.
- 같은 링크를 나중에 다시 열어도 같은 화면이 나온다.

### 4.5 만료 또는 사용된 링크 (`expired` / `invalid`)

| 위치 | 문구 |
|---|---|
| 제목 | 이 링크는 쓸 수 없어요 |
| 설명 | 링크가 만료됐거나 올바르지 않아요. 인증 링크는 24시간 동안 쓸 수 있어요. |
| 해결 안내 | 아래에서 메일을 다시 받거나, 처음부터 다시 가입해 주세요. |
| 버튼 1 | 메일 다시 받기 (기존 `ResendConfirmationForm`, 이메일 입력 칸 포함) |
| 버튼 2 | 처음부터 다시 가입하기 |
| 보조 링크 | 이미 가입을 마쳤다면 로그인하기 |
| 전화 | 어려우면 전화로 문의해 주세요. 전화 `{siteConfig.phone}` / 운영시간 `{siteConfig.supportHours}` |

- 제목을 정의서 초안 "링크가 만료됐거나 올바르지 않아요"에서 "이 링크는 쓸 수 없어요"로 바꿨다. 잠김 제목("이 링크는 더 쓸 수 없어요")과 짝이 되고, 제목에서 이미 해야 할 일이 분명하다. 이유("만료됐거나 올바르지 않아요")는 설명 첫 줄로 내렸다. 초안 제목을 유지해도 의미는 같다.
- 메일 다시 받기 성공 문구는 enumeration 문서의 것을 그대로 쓴다: "`{email}`로 메일을 보냈어요. 몇 분 안에 오지 않으면 스팸메일함을 확인해 주세요."
- 옛 링크나 보관 기간(7일)이 끝난 링크는 메일을 다시 받아도 메일이 가지 않을 수 있다(정의서 5.3절). 그래서 "처음부터 다시 가입하기"를 같은 비중으로 보여 준다. 버튼 순서를 바꾸려면 "다시 가입하기"를 앞에 둔다.
- 링크가 잘려 열린 경우도 같은 화면이다. 별도 문구를 두지 않는다.

### 4.6 이미 인증된 계정 (`done`)

| 위치 | 문구 |
|---|---|
| 제목 | 이미 가입을 마쳤어요 |
| 설명 | 이메일과 비밀번호로 로그인해 주세요. |
| 주 버튼 | 로그인하기 |
| 보조 안내 | 비밀번호가 기억나지 않으면 전화로 문의해 주세요. 전화 `{siteConfig.phone}` / 운영시간 `{siteConfig.supportHours}` |

- 이 화면은 비밀번호를 묻지 않는다. 가입을 마친 사람이 링크를 다시 열었을 때와, 확정 직후 응답이 끊겨 이 화면이 나왔을 때를 모두 감당한다. 후자를 위해 "방금 입력한 비밀번호로 로그인할 수 있어요"를 붙이는 안은 사용자가 방금 가입했는지 알 수 없어 사실과 다를 수 있다. 쓰지 않는다.
- 탈퇴한 계정의 링크는 이 화면이 아니라 4.5의 화면이다.

### 4.7 연결 오류와 429

| 상황 | 위치 | 문구 |
|---|---|---|
| 연결 오류(503·네트워크) | 입력 칸 위 | 지금 연결이 원활하지 않아요. 입력한 내용은 그대로예요. 잠시 후 다시 눌러 주세요. |
| 연결 오류, 처음 화면을 못 불러온 경우 | 화면 전체 | 제목: 지금 연결이 원활하지 않아요 / 설명: 잠시 후 다시 시도해 주세요. 계속 안 되면 전화로 문의해 주세요. 전화 `{siteConfig.phone}` / 운영시간 `{siteConfig.supportHours}` / 버튼: 다시 시도하기 |
| 429 | 입력 칸 위 | 요청이 많아요. 잠시 후 다시 시도해 주세요. 입력한 횟수에는 포함되지 않아요. |

- 연결 오류와 429는 남은 횟수를 줄이지 않는다. 시니어가 "한 번 날렸나" 걱정하지 않도록 429에 "입력한 횟수에는 포함되지 않아요"를 덧붙였다. 연결 오류에는 "입력한 내용은 그대로예요"를 쓴다. 단, 실제로 입력값을 유지하는지 개발 구현과 맞는지 확인이 필요하다(정의서 2.3절은 유지한다고 정함).
- 연결 오류는 서버가 확정 처리를 하다 실패했을 수도 있다. 이 경우 이어서 `done` 화면이 나오며 로그인으로 복구된다(정의서 5.9절). 별도 문구를 두지 않는다.
- 기존 문구 "다시 시도해주세요"는 "다시 시도해 주세요"로 띄어 쓴다(enumeration 문서 4장 #4).

### 4.8 상태 한눈에

| 상태 | 제목 |
|---|---|
| ready | 가입을 마무리해 주세요 |
| 틀림(1~4번째) | (ready 화면 위에 오류 표시) |
| locked | 이 링크는 더 쓸 수 없어요 |
| expired / invalid | 이 링크는 쓸 수 없어요 |
| done | 이미 가입을 마쳤어요 |
| 연결 오류(첫 화면) | 지금 연결이 원활하지 않아요 |

## 5. 관리자 회원 상세: 가입 마무리 전 회원 안내

위치: `app/(admin)/admin/members/[id]/page.tsx`. 미인증 회원일 때만 보이고, 이 회원에게는 `[이메일 인증완료 처리]` 버튼을 숨긴다.

| 위치 | 문구 |
|---|---|
| 배지(목록·대시보드·상세) | 가입 마무리 전 |
| 안내(상세 상단, 버튼 위) | 이 회원은 아직 가입을 마무리하지 않아 비밀번호가 없어요. 인증 처리 대신 [비밀번호 재설정 메일 발송]을 눌러 주세요. 회원이 메일의 링크에서 새 비밀번호를 정하면 가입도 함께 끝나요. |
| 안내 보조 | 재설정 메일은 가입 이메일로만 가요. 메일을 받은 사람이 곧 이메일 주인이니, 이름이 달라도 이메일만 확인하고 보내 주세요. |
| 인증 처리 거절(API 409 `password_not_set`, 직접 요청 시) | 비밀번호가 없는 계정은 인증 처리를 할 수 없어요. 비밀번호 재설정 메일을 보내 주세요. |
| 재설정 메일 발송 성공 | 비밀번호 재설정 메일을 보냈어요. (기존 문구 유지) |

- 관리자 화면이라 이모지·강조 색은 기존 규칙을 따른다. 안내는 노란 정보 상자(경고보다 낮은 단계)를 권한다.
- 버튼 이름은 기존 `[비밀번호 재설정 메일 발송]`을 바꾸지 않는다. 버튼 문구가 달라지면 운영자가 혼동한다.
- 이름·연락처는 미인증 회원이면 첫 가입 시도 값이라(공격자가 먼저 가입했다면 공격자 값일 수 있다) 본인 확인 기준으로 쓰지 않는다. 그래서 안내 보조 문구는 "이메일만 확인"으로 쓰고 이름 대조를 시키지 않는다(2026-11-26 개인정보 점검 B-1 반영).

안내 문구 옵션

| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (권장) | 이 회원은 아직 가입을 마무리하지 않아 비밀번호가 없어요. 인증 처리 대신 [비밀번호 재설정 메일 발송]을 눌러 주세요. ... | 이유와 할 일, 그 뒤 결과까지 한 번에 알려 준다. |
| B | 비밀번호가 없는 회원이라 인증 처리를 할 수 없어요. 재설정 메일을 보내 주세요. | 짧다. 거절 문구와 같아서 화면에 같이 두면 중복이다. 거절 문구 전용으로 쓴다. |

## 6. 전화 응대 스크립트 (운영자용)

이 스크립트는 운영자 문서용이며 회원에게 화면으로 보이지 않는다. 앱의 운영 절차 문서나 관리자 도움말에 옮겨 쓸 수 있다.

운영시간: `{siteConfig.supportHours}` (현재 평일 10:00~18:00, 점심 11:30~13:00 제외). 운영시간 밖의 전화는 메시지를 남기게 하고 다음 운영시간에 처리한다.

짧은 스크립트

1. 인사: "바라 평생교육원입니다. 무엇을 도와 드릴까요?"
2. 상황 확인: "가입할 때 정한 비밀번호가 기억나지 않으시는 거죠?"
3. 이메일 확인: "가입하신 이메일 주소를 불러 주시겠어요?"
4. 일치 확인: 관리자 회원 상세에서 그 이메일의 회원이 있는지만 본다. 있으면 5번, 없으면 아래 "확인이 안 될 때". 이름이 달라도 이메일이 맞으면 진행한다(미인증 회원의 이름은 처음 가입을 시도한 사람이 입력한 값일 수 있어요).
5. 안내하고 발송: "확인됐습니다. 지금 비밀번호 재설정 메일을 보내 드릴게요. 메일함을 확인해 주세요." 회원 상세에서 [비밀번호 재설정 메일 발송]을 누른다.
6. 다음 단계 안내: "메일의 링크를 열면 새 비밀번호를 정하는 화면이 나와요. 새 비밀번호를 정하면 가입도 함께 끝나요. 링크는 1시간 동안 쓸 수 있어요."
7. 메일이 안 올 때: "몇 분 지나도 안 오면 스팸메일함도 확인해 주세요. 그래도 없으면 다시 전화 주세요."
8. 마무리: "다른 궁금한 점은 없으세요? 감사합니다."

확인이 안 될 때
- 이메일로 회원을 찾을 수 없으면: "확인이 어려워 재설정 메일을 바로 보내 드리기 어렵습니다. 가입 화면에서 처음부터 다시 가입해 주세요. 새 인증 메일이 가요." 이유를 길게 설명하지 않는다.
- 이름이나 연락처는 확인 기준이 아니다. 이름이 다르다는 이유로 회원을 돌려보내거나 탓하지 않는다.

운영자가 지킬 점
- 비밀번호를 전화로 묻거나 말해 주지 않는다. 회원이 알려 주려 해도 받지 않는다("비밀번호는 말씀하지 않으셔도 돼요").
- 메일은 회원 메일함의 주인에게만 간다. 이메일 주소를 확인한 뒤 다른 주소로 보내 달라는 요청은 받지 않는다.
- 이름은 묻지 않는다. 발송은 시스템의 `비밀번호 재설정 메일 발송` 감사 기록이 남는다.
- 위 확인 절차(이메일만 확인)는 대표 결정 6번을 2026-11-26에 개인정보 점검(B-1)에 따라 고친 것이다. 더 엄격하게 바꾸려면 별도 결정이 필요하다.

## 7. 확인이 필요한 것

- 4.1 제출 중 문구("확인하고 있어요" 대 "확인하는 중이에요")를 하나로 정해 다른 화면과 통일.
- 4.7 연결 오류 때 입력한 비밀번호를 화면에 그대로 두는지는 frontend-developer 구현에 따라 문구가 사실과 맞아야 한다. 유지하지 않는다면 "입력한 내용은 그대로예요"를 빼야 한다.
- 3장 메일 `after`에 추가하는 "링크가 열리지 않으면" 한 줄은 선택이다. `ses.ts` 변경과 함께 qa-reviewer가 메일 본문 테스트를 갱신해야 한다.
- 5장 프로필 확인 안내는 마이페이지에서 이름·연락처 수정이 가능한지(대표 결정 6번 후단) 확인한 뒤 문구를 다듬는다. 수정이 가능하면 "가입을 마친 회원이 마이페이지에서 직접 고칠 수 있어요"를 덧붙일 수 있다.
- 이 문서는 문구만 확정한다. 정의서 7장의 초안 문구와 어긋나는 곳은 이 문서가 우선한다(바뀐 곳: 가입 직후 본문 2, 메일 제목·본문, 만료 제목, 불일치 도움말 합치기, 잠김 설명, 429·연결 오류 보강).
