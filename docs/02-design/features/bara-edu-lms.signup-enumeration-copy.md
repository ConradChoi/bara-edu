# 회원가입 문구 (이메일 열거 방지) — 카피 문서

- 작성일: 2026-11-25
- 근거: 대표 결정 2026-11-25. 화면은 가입 여부와 관계없이 항상 같은 안내를 보여 주고, 이미 가입된 주소에는 '이미 가입된 계정' 안내 메일을 보낸다.
- 말투: 쉬운 '~해요'체. 이모지·느낌표 없음. 사용자를 탓하지 않는다.
- 범위: 문구만. 코드는 바꾸지 않았다. 코드 변경이 필요한 부분은 4장에 따로 적었다.

## 1. 현재 동작 확인 (api/src/auth/service.ts)

| 상황 | signup() 결과 | 지금 보내는 메일 | 지금 화면 |
|---|---|---|---|
| 신규 | `pending_confirmation` | 인증 메일 | "인증 메일을 보내드렸어요" |
| 가입 + 인증 완료 | `already_registered` | 없음 | 에러 "이미 가입된 이메일이에요" (열거 지점) |
| 가입 + 인증 미완료 | `already_registered` (insert가 `on conflict do nothing`이라 인증 여부를 보지 않음) | 없음 | 위와 같은 에러 |

핵심: 미인증 기존 계정도 지금은 인증 메일을 새로 받지 못하고 "이미 가입된 이메일"만 보게 된다. 사용자는 "로그인해 주세요"를 따라 로그인하면 인증 안내 화면으로 가서 재전송을 눌러야 한다. 새 방식에서는 이 경우를 '인증 메일 다시 보내기'로 처리하길 제안한다(4장 코드 요청 1).

화면은 세 경우 모두 같아야 하므로, 메일 종류는 서버가 나눠 보낸다.

| 상황 | 화면 | 메일 |
|---|---|---|
| 신규 | 같은 문구 | 인증 메일 (기존 `confirm`) |
| 기존, 인증 완료 | 같은 문구 | 이미 가입된 계정 안내 (새 템플릿) |
| 기존, 미인증 | 같은 문구 | 인증 메일 새로 발송 (`confirm`, resendConfirmation과 같은 처리) |

## 2. 가입 제출 후 화면 안내 (components/auth/AuthForm.tsx, signup 모드)

세 경우 모두 같은 문구. 가입 여부를 암시하는 말("인증 메일", "이미", "다시")은 쓰지 않는다. 메일 종류가 다를 수 있어서 "인증 메일"이라고 단정하지 않고 "안내 메일"로 쓴다.

**제목(새로 추가 제안)**
- 메일을 보냈어요

**본문**
- `{email}`로 안내 메일을 보냈어요. 메일함을 확인해 주세요.
- 가입이 처음이면 메일 안의 링크를 눌러 가입을 마칠 수 있어요.

**메일이 안 올 때 (보조 안내)**
- 몇 분이 지나도 메일이 없다면 스팸메일함을 확인해 주세요.
- 입력한 이메일 주소가 맞는지도 확인해 주세요.
- 그래도 없으면 전화로 문의해 주세요. 010-9025-5093

**링크/버튼**
- 로그인 화면으로 (유지)
- 이메일 주소를 잘못 썼다면: 처음부터 다시 쓰기 (신규 제안. 같은 화면의 새 링크. `/sign-up` 이동)

### 옵션 비교 (본문 첫 줄)

| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (권장) | `{email}`로 안내 메일을 보냈어요. 메일함을 확인해 주세요. | 가입 여부를 전혀 드러내지 않는다. 시니어도 할 일이 한 가지로 분명하다. |
| B | `{email}`로 메일을 보냈어요. 메일에 적힌 안내를 따라 주세요. | 더 짧다. 다만 "무슨 안내"인지 흐려 불안할 수 있다. |
| C | 가입을 시작했어요. `{email}`로 보낸 메일을 확인해 주세요. | 신규 가입자에게는 자연스럽지만, 기존 회원에게는 사실과 달라 오해를 줄 수 있다. 비권장. |

### 재전송 영역 (ResendConfirmationForm) 문구

- 안내줄 (현재 "메일이 안 왔거나 링크가 만료됐다면 다시 보낼 수 있어요.") → 유지 가능. 위 2장 "메일이 안 올 때" 문구와 겹치므로 아래처럼 한 블록으로 합치길 제안한다.
  - "메일이 오지 않았거나 인증 링크가 만료됐나요? 아래에서 메일을 다시 받을 수 있어요."
- 입력칸 placeholder: 가입한 이메일 주소 (유지)
- 버튼: 인증 메일 재전송 → **메일 다시 받기** (동사 중심, 받는 결과가 분명함. 가입 상태를 암시하지 않음)
- 진행 중: 보내는 중... → 보내는 중이에요 (말투 통일. 선택)
- 성공 (현재 "`{email}`로 인증 메일을 다시 보냈어요."): 서버가 존재하지 않는 주소나 이미 인증된 주소에도 같은 응답을 주므로, 사실이 아닌 단정이 된다. 아래로 바꿔 주세요.
  - "`{email}`로 메일을 보냈어요. 몇 분 안에 오지 않으면 스팸메일함을 확인해 주세요."
- 실패 (현재 "인증 메일을 다시 보내지 못했어요. 잠시 후 다시 시도해주세요"):
  - "메일을 보내지 못했어요. 잠시 후 다시 시도해 주세요. 계속 안 되면 전화로 문의해 주세요. 010-9025-5093"
- 서버 60초 제한(`resend-miss`)이 걸리는 경우에도 위 성공 문구가 나가도록 되어 있다. 같은 이메일에 연달아 누르면 메일이 안 올 수 있으니 성공 문구에 "1분 뒤에 다시 눌러 주세요"를 붙이는 안은 4장에서 따로 제안한다.

## 3. '이미 가입된 계정' 안내 메일

### 제목
- **[바라 평생교육원] 이미 가입된 이메일이에요**

옵션
| 옵션 | 제목 | 뉘앙스 |
|---|---|---|
| A (권장) | [바라 평생교육원] 이미 가입된 이메일이에요 | 메일을 열기 전에 상황이 이해된다. |
| B | [바라 평생교육원] 가입 안내 | 중립적이지만 내용이 안 보여 지나치기 쉽다. |
| C | [바라 평생교육원] 로그인 안내 | 할 일이 분명하다. 다만 가입을 시도한 사람은 "로그인"과 헷갈릴 수 있다. |

### 본문 (텍스트)

```
안녕하세요. 바라 평생교육원이에요.

이 이메일 주소로 회원가입 요청이 있었어요.
이 주소는 이미 가입되어 있어서 새로 가입하지 않았어요.

아래 링크에서 로그인해 주세요.
{로그인 링크}

비밀번호가 기억나지 않으면 전화로 문의해 주세요.
전화: 010-9025-5093

본인이 가입을 시도한 것이 아니라면 이 메일을 무시해 주세요.
아무것도 바뀌지 않아요.

바라 평생교육원
```

- 마지막 문단 "아무것도 바뀌지 않아요"는 이전 비밀번호·계정이 그대로임을 알려 불안을 줄인다.
- "비밀번호 재설정은 관리자가 메일로 보내 드려요"는 일부러 넣지 않았다. 전화 문의 한 가지 행동만 남겨 간단하게 했다. 필요하면 "전화로 문의하시면 비밀번호 재설정 메일을 보내 드려요."로 바꿀 수 있다(비밀번호 문의 문구 옵션은 아래).

비밀번호 문의 문구 옵션
| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (권장) | 비밀번호가 기억나지 않으면 전화로 문의해 주세요. | 요청 그대로. 짧다. |
| B | 비밀번호가 기억나지 않으면 전화로 문의해 주세요. 확인 후 재설정 메일을 보내 드려요. | 다음에 일어날 일까지 알려 주지만, 본인 확인 절차 약속처럼 읽힐 수 있어 운영과 맞는지 확인이 필요하다. |

### 버튼 문구 (로그인 링크)
- **로그인하기** → `{origin}/sign-in`
- 현재 SES 메일은 HTML 버튼 없이 링크 한 줄만 보여 준다(ses.ts 28행). 버튼형 HTML을 쓰려면 위 문구를 버튼에, 링크 주소는 그 아래에 한 번 더 적어 주세요(버튼이 안 보이는 메일앱 대비).
- 로그인 이동 문구 옵션: A "로그인하기"(권장, 동사 중심) / B "로그인 화면으로 가기" / C "바라 평생교육원 로그인"(명사형이라 비권장).

### HTML 메일용 구조 (ses.ts에 넣을 때)
1. 인사 + 상황 두 줄
2. 버튼: 로그인하기
3. 비밀번호 문의 + 전화번호
4. 무시해도 된다는 문장
5. 서명: 바라 평생교육원

## 4. 기존 메일·화면과 어긋나는 곳 (맞춤 제안)

| # | 위치 | 지금 | 문제 | 제안 |
|---|---|---|---|---|
| 1 | 메일 제목 접두 (ses.ts 8, 12행) | `[바라평생교육원]` | 사이트 이름은 "바라 평생교육원"(site-config)인데 띄어쓰기가 다르다 | `[바라 평생교육원]`으로 통일 |
| 2 | 인증 메일 본문 (ses.ts 9행) | 링크 안내만 있고 가입을 시도하지 않은 경우의 안내가 없다 | 재설정 메일(13행)에는 "요청하지 않았다면 무시해 주세요"가 있는데 인증 메일에는 없다. 남이 내 주소로 가입을 시도할 수 있으므로 필요하다 | "아래 링크를 눌러 이메일 인증을 완료해 주세요. 링크는 24시간 동안 유효해요. 본인이 가입을 요청하지 않았다면 이 메일을 무시해 주세요." |
| 3 | 두 메일 공통 | 인사·서명·문의처가 없다 | 시니어가 스팸으로 오해할 수 있다 | 첫 줄 "안녕하세요. 바라 평생교육원이에요." 끝줄 서명과 전화 문의 추가(위 3장 형식과 통일) |
| 4 | 화면 에러 문구 | "다시 시도해주세요", "입력해주세요" (붙여 씀) | 메일은 "해 주세요"(띄어 씀) | 한글 맞춤법상 "해 주세요"가 맞다. 화면 문구도 "해 주세요"로 통일 (auth.ts 38, 64, 78, 84, 108행 등) |
| 5 | 인증 안내 화면 (AuthForm 24행) | "로 인증 메일을 보내드렸어요" | "보내드렸어요"는 "보냈어요"보다 어렵고, 회원가입 직후와 로그인 시 인증 전 계정 두 곳에서 같이 쓰인다. 또한 가입 화면에서 기존 회원에게도 보여 주므로 "인증 메일"이 사실이 아닐 수 있다 | 가입 화면은 2장 문구. 로그인 후 인증 전 계정 안내는 아래 4번 코드 요청 3 참고 |
| 6 | 존댓말 혼용 | "보내드려요"(sign-in/page.tsx 32), "보내드렸어요" | 같은 화면군에서 "보내 드려요/보내드려요/보냈어요" 혼재 | 쉬운 말 "보내요/보냈어요"로 통일. 예: "가입한 이메일을 입력하면 인증 메일을 다시 보내요." (sign-in/page.tsx 32행은 "메일 다시 받기" 버튼과 맞추어 "가입한 이메일을 입력하면 메일을 다시 보내요."로) |
| 7 | 용어 | "인증 메일 / 인증 링크 / 이메일 인증" | 같은 개념이 섞임 | 정한 용어: 가입 직후에 받는 메일은 **인증 메일**, 안에 있는 것은 **인증 링크**, 하는 일은 **이메일 인증**. 단 가입 화면과 재전송 성공 문구는 가입 여부를 숨겨야 해서 **메일**이라고만 쓴다 |

### 코드 요청 (문구가 성립하려면 필요한 것, 개발 담당 전달용)

1. **signup 서버 분기**: `on conflict do nothing`으로 끝나면 `already_registered`만 돌려주고 인증 여부를 보지 않는다. 기존이 인증 전이면 `confirm` 메일을 새로 보내고, 인증 완료면 새 `already_registered` 템플릿 메일을 보내야 위 1장 표대로 된다. 화면(auth.ts 47행)은 두 경우 모두 `{ pendingConfirmation: true, email }`를 돌려줘야 한다. `MailMessage.template`에 `'already_registered'`를 추가하고 `link`는 `{origin}/sign-in`으로 한다.
2. **응답 시간·속도 차이**: 신규는 인증 토큰 발급이 더 들어가므로, 응답 시간으로도 구분될 수 있다. 메일 발송은 응답 뒤 큐로 처리되어 있어(MailDeliver) 큰 차이는 없지만 확인이 필요하다. 문구 범위 밖이라 참고만 적는다.
3. **로그인 시 인증 전 계정 화면**: `login`이 `email_not_confirmed`일 때도 같은 `pendingConfirmation` 화면을 보여 주는데, 이때는 메일을 새로 보내지 않았다. 가입 화면 문구(2장)를 그대로 쓰면 "메일을 보냈어요"가 사실이 아니게 된다. 두 가지 중 하나를 권한다.
   - 방법 A: 로그인 쪽은 "이메일 인증이 아직 끝나지 않았어요. 받은 인증 메일의 링크를 눌러 주세요. 메일이 없으면 아래에서 다시 받을 수 있어요."라는 별도 문구를 쓴다. (비밀번호가 맞은 사람에게만 보이므로 열거 위험이 낮다)
   - 방법 B: 두 곳 모두 "메일을 보냈어요"로 쓰고 실제로 로그인 시에도 메일을 보낸다.
4. **재전송 응답 지연 안내(선택)**: 60초 제한 때문에 연타하면 메일이 안 갈 수 있다. 성공 문구에 "1분 뒤에 다시 눌러 주세요"를 더할지 정책 확인 필요.

## 5. 용어집 추가

| 용어 | 쓰는 곳 | 쓰지 않는 말 |
|---|---|---|
| 안내 메일 | 가입 제출 후 화면 (가입 여부를 숨겨야 할 때) | 확인 메일, 알림 메일 |
| 인증 메일 / 인증 링크 | 신규·미인증 가입자에게 가는 메일 | 확인 메일, 컨펌 메일 |
| 로그인하기 | 로그인 이동 버튼 | 로그인 하러 가기, 로그인 바로가기 |
| 메일 다시 받기 | 재전송 버튼 | 재전송, 재발송 (어려운 말) |
| 전화로 문의해 주세요 | 비밀번호·메일 문제의 최종 안내 | 고객센터에 연락 |

## 6. 확인이 필요한 것

- 전화 문의 시간(평일 몇 시까지)이 `siteConfig`에 없다. 시니어가 전화를 걸 시간이므로 있으면 같이 적는 것이 좋다. 전화번호는 하드코딩하지 말고 `siteConfig.phone`을 가져다 쓰세요.
- 옵션 B(재설정 메일을 보내 준다는 약속)는 운영 정책 확인 후 결정.
- 구현 후 `test/lib/db/auth.test.ts`의 기대값(`already_registered` 에러, 인증 메일 재전송 실패 문구)도 문구에 맞춰 바뀌어야 한다. 문서 동기화 원칙에 따라 menu-features/flows도 함께 갱신 필요.
