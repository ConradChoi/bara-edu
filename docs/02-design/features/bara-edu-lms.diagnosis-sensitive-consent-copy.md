## 2. `/selfcheck/start` 1페이지 — 동의 영역

배치 순서: ① 개인정보 수집·이용 → ② 민감정보 처리 → ③ 만 14세 이상. 각각 별도 상자·체크박스·오류 문구. 모두 미체크가 기본이고 "모두 동의"는 없다.

표시 규칙: 각 항목의 **요약**은 굵게, **자세히**는 바로 뒤에 보통 굵기로 둔다. 둘 다 상자 안에 항상 보인다(접지 않는다). 요약은 법이 요구하는 "중요한 내용의 명확한 표시"를 맡는다.

### 2.1 ① 개인정보 수집·이용 동의 (기존 상자 수정)

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| SC-PRIV-TITLE | 상자 제목 | 개인정보 수집·이용 동의 (필수) |
| SC-PRIV-ITEMS | 항목 | **항목**: 이름, 휴대전화 또는 이메일(1개 이상), 도형심리 학습 경험, 보유 자격 수준(적은 경우) |
| SC-PRIV-PURPOSE | 목적 | **목적**: 자가진단 결과를 본인에게 연결하고, 추천 과정을 안내하고, 강사과정 상담 때 연락하기 위해 써요. |
| SC-PRIV-PERIOD | 보유 기간 | **보유 기간**: 회원 계정에 연결하지 않으면 진단한 날부터 90일이 지나면 지워요. 회원 계정에 연결하면 회원 탈퇴 때까지 보관해요. |
| SC-PRIV-REFUSE | 거부권 | **동의하지 않을 수 있어요.** 다만 동의하지 않으면 자가진단을 할 수 없어요. |
| SC-PRIV-CHECK | 체크박스 라벨 | 개인정보 수집·이용에 동의해요 (필수) |
| SC-PRIV-LINK | 라벨 옆 링크(새 창) | 전체 내용 보기 |
| SC-PRIV-LINK-SR | 위 링크의 스크린리더 이름 | 개인정보처리방침 전체 내용 보기, 새 창에서 열려요 |
| SC-PRIV-ERR | 미체크로 [다음] | 개인정보 수집·이용에 동의해야 자가진단을 시작할 수 있어요 |

- 기존 상자의 "30문항 응답"은 ②로 옮겼다. 두 상자가 같은 항목을 겹쳐 말하지 않는다.
- 기존 "이름·연락처만 자동 파기"는 대표 결정 2(결과 전체 삭제)와 맞지 않아 "지워요"로 바꿨다.
- 기존 링크는 라벨 문장 전체("개인정보 수집·이용")에 걸려 있어 체크하려다 링크를 누르기 쉽다. 라벨과 링크를 떼고, 라벨 전체를 눌러 체크되게 한다(정의서 4.1절 터치 영역).
- SC-PRIV-ERR는 기존 문구에서 "진단"을 "자가진단"으로만 맞췄다.

### 2.2 ② 민감정보 처리 동의 (신규, `sc-v1`)

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| SC-SENS-TITLE | 상자 제목("민감정보" 굵게) | 민감정보(자가진단 응답·결과) 처리 동의 (필수) |
| SC-SENS-WHAT | 제목 아래 첫 줄 | 민감정보는 법에서 더 조심해서 다루도록 정한 정보예요. |
| SC-SENS-INTRO | 그 아래 | 바라 평생교육원은 자가진단의 **응답과 결과를 민감정보로 보고**, 다른 개인정보와 따로 동의를 받아 아래와 같이 처리해요. |
| SC-SENS-PURPOSE-SUM | 목적 요약(굵게) | **처리 목적: 점수 계산과 결과 안내** |
| SC-SENS-PURPOSE-DETAIL | 목적 자세히 | 자가진단 점수를 계산하고, 결과와 추천 과정을 알려 드려요. 강사과정 사전 적합 후보로 나오면 강사과정 상담을 연결할 때에도 써요. |
| SC-SENS-ITEMS-SUM | 항목 요약(굵게) | **처리 항목: 30개 문항 응답과 그 결과** |
| SC-SENS-ITEMS-DETAIL | 항목 자세히 | 30개 문항에 대한 응답, 영역별 점수와 전체 점수, 강점·보완 영역, 추천 과정 |
| SC-SENS-PERIOD-SUM | 보유 기간 요약(굵게) | **보유 기간: 회원 계정에 연결하지 않으면 진단한 날부터 90일이 지나면 모두 지워요.** |
| SC-SENS-PERIOD-DETAIL | 보유 기간 자세히 | 회원 계정에 연결하면 **회원 탈퇴 때나 직접 지울 때(삭제 요청 포함)까지** 보관해요. 지운 결과는 결과 링크로도 열리지 않아요. |
| SC-SENS-REFUSE-SUM | 거부권 요약(굵게) | **동의하지 않을 수 있어요. 다만 동의하지 않으면 자가진단을 할 수 없어요.** |
| SC-SENS-REFUSE-DETAIL | 거부권 자세히 | 강좌 정보 보기와 전화 상담은 동의 없이 이용할 수 있어요. |
| SC-SENS-LINK-NOTICE | 네 항목 아래, 체크박스 위(공개 가능성 고지) | 결과 화면 주소(결과 링크)를 아는 사람은 누구나 추천 과정과 전체 점수를 볼 수 있어요. 결과 링크는 다른 사람에게 보내지 않도록 조심해 주세요. |
| SC-SENS-CHECK | 체크박스 라벨 | 자가진단 응답과 결과를 민감정보로 처리하는 데 동의해요 (필수) |
| SC-SENS-WITHDRAW | (선택) 체크박스 아래 보조 한 줄 | 동의는 나중에 거둘 수 있어요. 회원은 마이페이지에서 진단 기록을 지우면 되고, 회원이 아니면 전화나 이메일로 요청해 주세요. |

- 4개 항목의 사실관계는 정의서 3.2절 그대로다. 바꾼 것: 항목마다 요약/자세히로 나눔, "진단일로부터 90일 뒤"를 "진단한 날부터 90일이 지나면"으로, "삭제를 요청할 때까지"를 회원 셀프 삭제(대표 결정 3)가 드러나게 "직접 지울 때(삭제 요청 포함)까지"로.
- SC-SENS-WHAT는 정의서에 없는 한 줄이다. "민감정보"는 해외 이주민·시니어에게 낯선 법률 용어라 한 번 풀어 둔다. 법정 고지 항목을 바꾸지 않는 설명 문장이다. 상자 길이가 부담되면 이 줄부터 뺀다.
- SC-SENS-WITHDRAW는 법정 고지 4개에 들지 않는 선택 문구다. 넣으면 "동의는 쉽게, 철회는 어렵게"로 보이지 않는 장점이 있고, 상자가 한 줄 길어진다. 넣을지는 privacy-security-officer가 정한다. 넣든 빼든 `sc-v1` 원문을 확정한 뒤에는 고치지 않는다.
- 문장 끝 "보내지 마세요"(정의서 초안)를 "보내지 않도록 조심해 주세요"로 바꿨다. 금지보다 당부가 교육·인증형 톤에 맞고, 뜻은 같다.
- SC-SENS-CHECK 옵션

| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (권장) | 자가진단 응답과 결과를 민감정보로 처리하는 데 동의해요 (필수) | 무엇에 동의하는지 라벨만 읽어도 알 수 있다. 스크린리더가 라벨만 읽어도 뜻이 통한다. |
| B | 위 민감정보(자가진단 응답·결과) 처리에 동의해요 (필수) | 정의서 초안. 제목과 같은 말이라 짝이 분명하지만 "위"가 가리키는 곳을 봐야 이해된다. |
| C | 민감정보 처리에 동의해요 (필수) | 가장 짧다. 무엇이 민감정보인지 라벨에 없어 ①과 헷갈릴 수 있다. 비권장. |

### 2.4 ② 미체크 — 거부·차단 상태와 대안

[다음]을 눌렀는데 ②가 비어 있을 때, 체크박스 ② 바로 아래에 나온다. 포커스는 체크박스 ②로 간다. ②를 체크하면 영역 전체가 사라진다.

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| SC-SENS-ERR | 체크박스 아래 첫 줄(오류) | 자가진단을 하려면 이 동의가 필요해요. |
| SC-REFUSE-NOTSENT | 그 아래 | 아직 회사로 보낸 정보는 없어요. |
| SC-REFUSE-ALT-TITLE | 대안 안내 제목 | 동의 없이도 이렇게 도움받을 수 있어요 |
| SC-REFUSE-COURSES | 버튼형 링크(`/courses`, 같은 탭) | 강좌 둘러보기 |
| SC-REFUSE-PHONE | 전화 링크(`tel:`) | 전화로 상담받기 `{siteConfig.phone}` |
| SC-REFUSE-HOURS | 전화 링크 아래 | 운영시간 `{siteConfig.supportHours}` |

- SC-REFUSE-NOTSENT는 사실이다. 1페이지에서는 서버로 아무것도 보내지 않는다(정의서 1.2절 거부 3). 동의를 망설이는 사람에게 "이미 정보가 넘어갔나" 하는 걱정을 덜어 준다. 다만 입력값은 브라우저 초안(24시간)에 남으므로 "저장되지 않았어요"라고는 쓰지 않는다.
- SC-SENS-ERR 옵션

| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (권장) | 자가진단을 하려면 이 동의가 필요해요. | 하려는 일(자가진단)에서 시작해 필요한 것을 말한다. 사용자를 막는 느낌이 덜하다. ①의 오류 문구와 문형이 같다. |
| B | 이 동의가 없으면 자가진단을 할 수 없어요. | 정의서 초안. 사실은 같지만 "할 수 없어요"로 끝나 거절로 읽힌다. |
| C | 이 동의에 체크해 주세요. | 할 일만 말한다. 왜 필요한지 빠져 대안 안내와 이어지지 않는다. 비권장. |

| SC-DRAFT-CONSENT | 본문 둘째 줄(추가) | 동의는 첫 화면에서 다시 해 주세요. |
| SC-DRAFT-SHARED | 본문 셋째 줄(추가) | 다른 사람이 쓰던 기기라면 [새로 시작하기]를 눌러 주세요. |
| SC-DRAFT-NEW | 보조 버튼(기존 유지) | 새로 시작하기 |
| SC-DRAFT-CONTINUE | 주 버튼(기존 유지) | 이어서 하기 |

- SC-DRAFT-CONSENT는 정의서의 "동의 항목은 다시 체크해 주세요"를 바꿨다. 이어서 하면 항상 1페이지부터 시작하므로(정의서 4.2절) "어디서" 할지를 말해 준다.

## 3. 제출 오류 (`/selfcheck/start?error=`)

1페이지 상단 알림에 나온다. 화면은 1페이지로 돌아온다.

| 슬롯 ID | 코드 | 문구 |
|---|---|---|
| SC-ERR-VALIDATION | `validation`(기존 유지, 동의 누락 포함) | 필수 항목을 확인해 주세요. |
| SC-ERR-CONSENT | (선택, 신규 코드 `consent-required`) 동의 ①·② 중 하나라도 없이 제출됨 | 자가진단을 하려면 동의가 필요해요. 아래 동의 항목을 확인해 주세요. |
| SC-ERR-OUTDATED | `consent-outdated`(신규) | 동의 안내가 바뀌었어요. 바뀐 내용을 읽고 다시 동의해 주세요. 입력한 답은 그대로예요. |
| SC-ERR-INCOMPLETE | `incomplete`(기존 유지) | 아직 응답하지 않은 문항이 있어요. |
| SC-ERR-FAILED | `submit-failed`(기존 유지) | 제출에 실패했어요. 잠시 후 다시 시도해 주세요. |

- 동의 없이 제출되는 경우는 화면 검사를 건너뛴 경우(스크립트 꺼짐, 뒤로 가기로 체크 해제 등)뿐이다. 정의서는 이를 `validation`으로 묶는다. 그 경우 "필수 항목"이 무엇인지 알 수 없어, 동의 누락만 따로 알려 주는 SC-ERR-CONSENT를 제안한다. 코드를 새로 두려면 frontend-developer와 정해야 한다. 두지 않으면 SC-ERR-VALIDATION을 그대로 쓴다.
- SC-ERR-OUTDATED는 정의서의 "입력하신 답은 남아 있어요"를 비밀번호 찾기 문구와 같은 "입력한 … 그대로예요"로 맞췄다. 브라우저 초안에서 답을 복원할 수 있을 때만 이 문장을 쓴다. 초안이 없으면(다른 기기 등) 둘째 문장까지만 쓴다.
- "동의 내용"을 "동의 안내"로 바꿨다. 바뀐 것은 사용자가 아니라 회사가 보여 준 안내문이다.

## 5. 진단 기록 지우기 (마이페이지 `/my?tab=diagnosis`, 결과 상세 공통)

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| SC-MY-DEL-BTN | 마이페이지 각 행 오른쪽 텍스트 버튼 | 지우기 |

| SC-DEL-CONFIRM-OK | 주 버튼(위험 색) | 지우기 |
| SC-DEL-CONFIRM-CANCEL | 보조 버튼 | 그대로 두기 |
| SC-DEL-BUSY | 지우는 중(버튼) | 지우는 중이에요 |
| SC-MY-DEL-DONE | 성공, 목록 위 배너(`deleted=1`) | 진단 기록을 지웠어요. |
| SC-MY-DEL-FAIL | 실패, 목록 위 알림(목록 유지) | 진단 기록을 지우지 못했어요. 잠시 후 다시 시도해 주세요. 계속 안 되면 전화로 문의해 주세요. 전화 `{siteConfig.phone}` |
| SC-MY-EMPTY | 빈 상태 | 아직 자가진단 기록이 없어요 |
| SC-MY-EMPTY-BTN | 빈 상태 버튼(기존 유지) | 도형심리 역량진단 받아보기 |

- 보조 버튼을 정의서의 "취소"에서 "그대로 두기"로 바꿨다. "취소"는 "기록을 취소(삭제)한다"로도 읽혀 시니어가 헷갈릴 수 있다. 누르면 무엇이 되는지 바로 보인다.
- SC-DEL-CONFIRM-LEAD-HELP는 체크를 풀었을 때 결과를 알려 준다(v9·v10 처리방침 제3조, 상담 문의 1년). 상담 문의가 있는지 화면이 알 수 없다면 체크박스와 도움말을 둘 다 빼고 항상 함께 지운다(backend-developer와 확정).
- SC-MY-EMPTY는 기존 "아직 자가진단 이력이 없어요"에서 "이력"을 "기록"으로만 바꿨다. 지우는 대상을 "진단 기록"이라 부르므로 같은 화면에서 단어를 맞춘다. 탭 이름 "자가진단내역"은 내비게이션이라 그대로 둔다.
- 마지막 기록을 지우면 SC-MY-DEL-DONE 배너와 SC-MY-EMPTY가 함께 보인다. 따로 문구를 두지 않는다.
- 실패 원인(남의 결과, 이미 없음, 서버 오류)은 구분하지 않는다(정의서 11.3절).
- SC-DEL-CONFIRM-CANCEL 옵션

| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (권장) | 그대로 두기 | 누르면 기록이 남는다는 결과가 분명하다. |
| B | 취소 | 정의서 초안. 짧고 익숙하지만 "삭제를 취소"인지 "기록을 취소"인지 모호하다. |
| C | 닫기 | 중립적이다. 기록이 남는지는 말해 주지 않는다. |

## 7. 배포 때 지워지는 기존 결과에 대한 안내

- 결과 링크 화면: **새 안내를 두지 않는다.** 정의서 11.2절이 "배포 당일 정리하므로 별도 화면 없음"으로 정했다. 지워진 링크는 4장의 SC-RES-NOTFOUND-* 를 보게 되며, SC-RES-NOTFOUND-DESC의 둘째 문장이 "링크가 틀렸나" 하는 오해를 줄인다.
- 마이페이지: 기록이 지워진 회원은 SC-MY-EMPTY를 본다. 별도 배너를 두지 않는다.
- 회원 안내 메일(선택, 정의서 7장): 외부 실사용자 회원이 있을 때만 대표가 회사 메일함에서 보낸다. 비회원에게는 보내지 않는다. 쓸 경우의 문구:

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| SC-MAIL-SUBJECT | 제목 | [바라 평생교육원] 자가진단 기록을 정리했어요 |
| SC-MAIL-BODY-1 | 본문 1 | 안녕하세요. 바라 평생교육원이에요. |
| SC-MAIL-BODY-2 | 본문 2 | 이제 도형심리 자가진단의 응답과 결과를 민감정보로 다루고, 시작할 때 따로 동의를 받아요. |
| SC-MAIL-BODY-3 | 본문 3 | 그 전에 하신 자가진단 기록은 이 동의를 받지 않았기 때문에 `{삭제일}`에 모두 지웠어요. |
| SC-MAIL-BODY-4 | 본문 4 | 자가진단은 아래 주소에서 언제든 다시 해 볼 수 있어요. https://bara-edu.kr/selfcheck |
| SC-MAIL-BODY-5 | 본문 5 | 궁금한 점은 전화 `{전화}`(운영시간 `{운영시간}`)나 info@ylia.io로 문의해 주세요. |

- 메일에 점수·추천 과정 등 지운 내용을 적지 않는다. "회원님의 결과는 ○○였어요" 같은 말을 쓰면 지운 민감정보를 메일로 다시 남기게 된다.

## 8. 확인이 필요한 것

- `sc-v1` 원문 확정 범위: SC-SENS-TITLE부터 SC-SENS-CHECK까지(SC-SENS-WITHDRAW를 넣으면 포함). privacy-security-officer 확인 뒤 `data/diagnosis/consent.ts`에 넣고 그 뒤로는 고치지 않는다.
- SC-ERR-CONSENT(`consent-required` 코드) 도입 여부: frontend-developer.
- SC-DEL-CONFIRM-LEAD를 보이려면 화면이 상담 문의 유무를 알아야 한다: backend-developer.
- 처리방침 원고(9장) 제8조 (6)에는 "저장 시 암호화" 문장을 **넣지 않았다.** RDS 저장·스냅샷 암호화가 켜져 있다고 확인되면 9.3절의 추가 문장을 붙인다(정의서 8.7절 조건).
- 백업 보관(정의서 6장 "백업에서는 최대 N일 뒤 사라져요"): 원고에 넣지 않았다. RDS 자동 백업 보관 기간을 확인한 뒤 privacy-security-officer가 넣을지 정한다.
- 공고·시행일: 정의서 9.3절 배포 순서상 v10을 먼저 게시하고 곧바로 앱을 배포한다. 시행일은 앱 배포일과 같게 잡는 것을 권한다(게시와 배포 사이에는 방침에 적힌 별도 동의가 화면에 아직 없다). 대표 결정으로 7일 전 공지는 생략한다. 제11조 (2)의 문장은 바꾸지 않았다.
- 저장소 `docs/01-plan/features/bara-edu-lms.legal-privacy.md`를 9장 본문과 똑같이 맞추는 일은 정의서 12장대로 따로 한다.

```text

회사는 서비스 제공에 필요한 최소한의 개인정보만을 수집합니다.
```

메모
- 17번: 관리자 목록은 접속 기록 없이 점수·추천 단계를 보여 준다(이름은 가림). 정의서 초안의 "응답·결과를 조회하거나 처리한 기록은 보관합니다"를 그대로 쓰면 목록 열람까지 기록하는 것처럼 읽혀 사실과 다르다. 그래서 "이름·연락처와 함께"(상세·개인정보 보기, 둘 다 기록됨)로 범위를 좁혔다.
- 19번 변경 사유의 "이 방침의 시행에 맞추어 모두 삭제합니다": 정의서 9.3절 순서상 v10 게시가 기존 결과 삭제보다 먼저라, 게시 시점에 "삭제했습니다"(과거형)는 사실이 아니다. 삭제 날짜를 넣고 싶으면 삭제 뒤에 v10을 다시 게시하지 않도록 미래형을 유지한다.
- 제11조 (2)의 "7일 전 고지" 문장은 그대로 두었다. 대표 결정은 이번 개정에만 공지 기간을 두지 않는 것이고, 조항 자체를 바꾸는 결정이 아니다. 이 점이 문제 되는지는 privacy-security-officer가 본다(정의서 8.8절).
- 제8조 (1)의 "데이터베이스 행 수준 접근제어(RLS)"는 이번 범위 밖이라 손대지 않았다. 서버 이전 뒤에도 사실인지 privacy-security-officer가 따로 확인하길 권한다.

### 9.3 조건부 추가 문장 (확인 뒤에만)

RDS 스토리지·스냅샷 암호화가 켜져 있다고 확인되면, 제8조 (6) 끝에 다음 문장을 붙인다. 확인 전에는 넣지 않는다.

```text
데이터베이스와 백업은 저장 시 암호화된 상태로 보관합니다.
```
