# 비밀번호 찾기 — 최종 문구 (카피 문서)

- 작성일: 2026-11-26
- 작성: ux-writer
- 근거: `bara-edu-lms.password-reset-request.md`의 9장 초안과 "대표 결정"(10장 1~9 모두 추천안). 이 문서가 9장 초안을 대체한다.
- 말투: 쉬운 `~해요`체. "해 주세요"처럼 띄어 쓴다. 이모지·느낌표 없음. 사용자를 탓하지 않는다. 한 문장에 할 일 하나.
- 범위: 문구만. 코드는 바꾸지 않았다. `{ }`는 화면이나 메일이 채우는 값이다.
- 전화번호와 운영시간은 하드코딩하지 않는다. 앱은 `siteConfig.phone`·`siteConfig.supportHours`, API 메일은 `api/src/mail/support.ts`의 `SUPPORT_PHONE`·`SUPPORT_HOURS`를 쓴다(메일 템플릿이 문의처를 자동으로 붙인다).
- 열거 방지: 이 문서의 어떤 문구도 이메일이 가입돼 있는지 알려 주지 않는다. 가입 여부와 관계없이 모든 요청에 같은 문구가 나온다.
- 슬롯 ID는 `FP-`(forgot-password), `EP-`(진입점), `RP-`(reset-password), `MAIL-`(메일) 접두어를 쓴다. 문구를 바꿔도 ID는 유지한다.

## 0. 용어 (이 기능 전용)

| 용어 | 쓰는 곳 | 쓰지 않는 말 |
|---|---|---|
| 비밀번호 찾기 | 화면 이름, 제목, 가입 직후 안내의 링크 | 비밀번호 복구, 계정 찾기 |
| 비밀번호 새로 정하기 | 가입 마무리·인증 대기 화면의 버튼, 링크 | 비밀번호 초기화, 리셋 |
| 재설정 메일 | 메일 이름. 처음 나올 때 "비밀번호를 새로 정하는 링크"로 풀어 쓴다 | 리셋 메일, 복구 메일 |
| 메일 다시 받기 | 보냄 화면의 버튼 | 재전송, 다시 보내기(받는 사람 기준으로 쓴다) |
| 비밀번호 변경 | `/reset-password`의 주 버튼, 성공 배너 | 비밀번호 수정, 저장 |
| 가입한 이메일 | 입력 칸 라벨 | 아이디, 계정 이메일 |
| 로그인 | 모든 화면 | 로그온, 접속 |

"다시 보내기"는 보내는 쪽 말이라 회원이 누르는 버튼에는 "메일 다시 받기"를 쓴다(가입 마무리 문서의 기존 버튼 이름과 같다).

## 1. `/forgot-password` 입력 화면

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| FP-TITLE | 제목(`h1`) | 비밀번호 찾기 |
| FP-DESC | 안내 | 가입한 이메일 주소를 입력해 주세요. 비밀번호를 새로 정하는 링크를 보내 드려요. |
| FP-LABEL | 칸 라벨 | 가입한 이메일 |
| FP-HELP | 칸 도움말 | 휴대폰 본인인증이나 이름·연락처는 묻지 않아요. 가입한 이메일만 있으면 돼요. |
| FP-BTN | 주 버튼 | 재설정 메일 받기 |
| FP-BTN-BUSY | 제출 중(버튼) | 보내는 중이에요 |
| FP-LINK-SIGNIN | 보조 링크 | 로그인 화면으로 |
| FP-FOOT | 하단 안내 | 이메일 주소가 기억나지 않거나 메일함을 열 수 없다면 전화로 문의해 주세요. 전화 `{siteConfig.phone}` / 운영시간 `{siteConfig.supportHours}` |
| FP-FOOT-LOGGEDIN | 로그인 상태일 때만(선택) | 로그인한 상태라면 [마이페이지]에서 바꿀 수 있어요. |

- FP-DESC를 초안의 한 문장에서 두 문장으로 나눴다. 한 문장에 조건과 결과가 같이 있으면 읽어 주기 도구와 번역기가 헷갈린다.
- FP-BTN은 "재설정 메일 받기"로 유지한다. 누르면 무엇이 오는지 예측할 수 있고, 초대형이다("메일 발송" 같은 명령형이 아니다).
- FP-FOOT-LOGGEDIN의 마이페이지 링크 이름은 기존 내비게이션 이름을 따른다.

### 1.1 오류 (입력 유지)

| 슬롯 ID | 상황 | 위치 | 문구 |
|---|---|---|---|
| FP-ERR-EMPTY | 칸이 비어 있음 | 칸 아래 | 이메일을 입력해 주세요 |
| FP-ERR-FORMAT | 형식이 올바르지 않음(서버 호출 없음) | 칸 아래 | 올바른 이메일 형식이 아니에요. 예: name@example.com |
| FP-ERR-429 | IP 제한(429) | 칸 위 알림 | 요청이 많아요. 잠시 후 다시 시도해 주세요. 입력한 이메일은 그대로예요. |
| FP-ERR-UNAVAILABLE | 연결 불가(503·네트워크) | 칸 위 알림 | 지금 연결이 원활하지 않아요. 입력한 이메일은 그대로예요. 잠시 후 다시 눌러 주세요. |
| FP-ERR-FAILED | 기타 실패(설정 오류 등) | 칸 위 알림 | 메일을 보내지 못했어요. 잠시 후 다시 시도해 주세요. 계속 안 되면 전화로 문의해 주세요. 전화 `{siteConfig.phone}` |

- FP-ERR-FORMAT에 예시를 덧붙였다. 해외 이주민이 형식을 이해하기 쉽다. 예시 도메인은 `example.com`으로 둔다.
- FP-ERR-429는 `MSG_RATE_LIMITED`("요청이 많아요. 잠시 후 다시 시도해 주세요")에 한 문장을 더했다. 429가 나온 화면에서 "입력이 사라졌나" 걱정하지 않게 한다. `MSG_RATE_LIMITED`를 그대로 재사용하려면 둘째 문장만 뺀다.
- FP-ERR-UNAVAILABLE도 `MSG_UNAVAILABLE`에 "입력한 이메일은 그대로예요"를 더했다. 실제로 입력값을 유지할 때만 쓴다.
- 이메일별 제한(60초 1회, 1시간 4회)에 걸려도 화면은 보냄 화면과 같다. 오류 문구를 따로 두지 않는다(열거 방지).

## 2. 보냄 화면

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| FP-SENT-TITLE | 제목(포커스 이동) | 메일함을 확인해 주세요 |
| FP-SENT-BODY | 본문(대표 결정 1: 조건 문구) | `{email}`로 안내를 보냈어요. 가입한 이메일이 맞다면 몇 분 안에 비밀번호를 새로 정하는 링크가 도착해요. 링크는 1시간 동안 쓸 수 있어요. |
| FP-SENT-IGNORE | 본문 아래 | 본인이 요청하지 않았다면 따로 하실 일은 없어요. |
| FP-SENT-NOMAIL-TITLE | 메일이 안 올 때 제목 | 메일이 오지 않나요? |
| FP-SENT-NOMAIL-1 | 도움말 1 | 몇 분이 지나도 없다면 스팸메일함을 확인해 주세요. |
| FP-SENT-NOMAIL-2 | 도움말 2 | 위에 적힌 이메일 주소가 맞는지 확인해 주세요. |
| FP-SENT-NOMAIL-3 | 도움말 3 | 그래도 없으면 전화로 문의해 주세요. 전화 `{siteConfig.phone}` / 운영시간 `{siteConfig.supportHours}` |
| FP-SENT-RESEND | 다시 받기(버튼) | 메일 다시 받기 |
| FP-SENT-RESEND-WAIT | 비활성일 때 보조문 | 1분 뒤에 다시 받을 수 있어요. 여러 번 눌러도 메일이 빨리 오지 않아요. |
| FP-SENT-RESEND-READY | 활성이 될 때(스크린리더 한 번) | 이제 메일을 다시 받을 수 있어요. |
| FP-SENT-RESEND-DONE | 다시 받기를 누른 뒤 한 줄 | 다시 요청했어요. 몇 분 안에 오지 않으면 스팸메일함을 확인해 주세요. |
| FP-SENT-OTHER | 보조 버튼 | 다른 이메일로 다시 입력하기 |
| FP-SENT-LINK-SIGNIN | 보조 링크 | 로그인 화면으로 |

- FP-SENT-BODY는 가입 화면의 "안내 메일을 보냈어요. 메일함을 확인해 주세요"와 문구가 다르다. 가입 여부를 단정하지 않으려고 일부러 달리 썼다. "가입한 이메일이 맞다면"이 가입 여부를 알려 주는 말이 아니라 "입력한 주소가 가입한 주소와 같다면"의 뜻이라는 점이 중요하다. 모든 요청에 같은 문장이 나온다.
- 같은 이유로 "메일을 보냈어요"가 아니라 "안내를 보냈어요"를 쓴다. 가입되지 않은 주소에는 실제로 메일이 가지 않는다.
- FP-SENT-NOMAIL-2에서 "입력한 이메일 주소"를 "위에 적힌 이메일 주소"로 바꿨다. 화면에서 가리키는 곳이 분명하다.
- FP-SENT-RESEND-DONE은 서버가 이메일 제한 때문에 메일을 안 보냈더라도 같은 문구를 쓴다. "다시 보냈어요"는 쓰지 않는다. 사실이 아닐 수 있다.
- FP-SENT-BODY 옵션

| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (확정, 대표 결정 1) | 가입한 이메일이 맞다면 몇 분 안에 비밀번호를 새로 정하는 링크가 도착해요. | 사실과 맞고 가입 여부를 드러내지 않는다. 조건절이 처음에는 낯설 수 있어 바로 뒤 FP-SENT-NOMAIL 블록이 보완한다. |
| B (미채택) | 안내 메일을 보냈어요. 메일함을 확인해 주세요. | 가입 화면과 같지만 가입되지 않은 주소에는 사실이 아니다. |

## 3. 진입 문구

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| EP-SIGNIN-LINK | 로그인 화면, 비밀번호 칸 바로 아래 한 줄 | 비밀번호를 잊으셨나요? |
| EP-PENDING-LOGIN | 로그인 시 인증 대기 화면(`source=login`), 기존 안내 아래 | 가입할 때 정한 비밀번호가 기억나지 않나요? 비밀번호를 새로 정하면 가입도 함께 끝나요. |
| EP-PENDING-LOGIN-BTN | 위 문구 아래 링크 버튼 | 비밀번호 새로 정하기 |
| EP-SIGNUP-DONE | 가입 직후 안내 화면, 보조 블록 | 비밀번호가 기억나지 않으면 [비밀번호 찾기]를 눌러 주세요. |
| EP-FINISH-FORGOT-TITLE | 가입 마무리, "기억나지 않아요" 접기 제목(기존 유지) | 비밀번호가 기억나지 않아요 |
| EP-FINISH-FORGOT-BODY | 같은 영역 본문 1(대표 결정 8: 먼저 둔다) | 이메일로 비밀번호를 새로 정할 수 있어요. 새로 정하면 가입도 함께 끝나요. |
| EP-FINISH-FORGOT-BTN | 같은 영역 주 버튼 | 비밀번호 새로 정하기 |
| EP-FINISH-FORGOT-ALT | 같은 영역 보조(주 버튼 아래) | 다른 방법: 처음부터 다시 가입하기 / 전화로 문의하기 `{siteConfig.phone}` |
| EP-LOCKED-DESC | 가입 마무리 `locked`, 설명 | 비밀번호가 5번 맞지 않아서 이 링크를 잠갔어요. 개인정보를 지키기 위한 조치예요. (기존 유지) |
| EP-LOCKED-GUIDE | `locked`, 해결 안내(변경) | 이메일로 비밀번호를 새로 정할 수 있어요. 새로 정하면 가입도 함께 끝나요. |
| EP-LOCKED-BTN | `locked`, 주 버튼(변경) | 비밀번호 새로 정하기 |
| EP-LOCKED-ALT | `locked`, 보조 | 처음부터 다시 가입하기 / 어려우면 전화로 문의해 주세요. 전화 `{siteConfig.phone}` / 운영시간 `{siteConfig.supportHours}` |
| EP-EXPIRED-LINE | 가입 마무리 `expired`·`invalid`, [메일 다시 받기] 아래 한 줄 | 비밀번호가 기억나지 않으면 [비밀번호 새로 정하기]를 눌러 주세요. |
| EP-EXPIRED-BTN | 위 줄의 링크 이름 | 비밀번호 새로 정하기 |

- 가입 직후 안내(EP-SIGNUP-DONE)에는 "이미"·"다시"를 쓰지 않는다. 가입 여부를 암시하기 때문이다. 링크 이름도 "비밀번호 찾기"로 중립적으로 둔다.
- 인증 대기 화면(EP-PENDING-LOGIN)은 로그인에서 비밀번호가 맞은 사람에게만 보인다(열거 방지 문서 방법 A). 그래서 "가입도 함께 끝나요"라고 말해도 안전하다. 가입 직후 안내에서는 이 말을 쓰지 않는다.
- locked/expired에서는 [비밀번호 새로 정하기]가 주 버튼이고 [처음부터 다시 가입하기]는 보조다. 순서만 바꾸고 기존 버튼 이름은 유지한다.
- EP-PENDING-LOGIN 옵션

| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (권장) | 가입할 때 정한 비밀번호가 기억나지 않나요? 비밀번호를 새로 정하면 가입도 함께 끝나요. | 질문으로 시작해 사용자를 탓하지 않는다. 결과까지 말해 준다. |
| B | 비밀번호가 기억나지 않으면 새로 정해 주세요. | 가장 짧다. 가입이 함께 끝난다는 이점이 빠진다. |

## 4. `/reset-password` 추가 문구

| 슬롯 ID | 상태 | 위치 | 문구 |
|---|---|---|---|
| RP-NOTICE | 정상(토큰 있음) | 입력 칸 위 안내 | 새 비밀번호를 정해 주세요. 변경하면 모든 기기에서 로그아웃돼요. |

| RP-EXPIRED-HELP | 같은 상태 | 알림 아래 | 링크는 1시간 동안, 한 번만 쓸 수 있어요. |
| RP-ERR-UNAVAILABLE | 연결 불가 | 칸 위 알림 | 지금 연결이 원활하지 않아요. 입력한 내용은 그대로예요. 잠시 후 다시 눌러 주세요. |
| RP-BTN-BUSY | 제출 중 | 버튼 | 변경하는 중이에요 |
| RP-SUCCESS | 성공 배너, `/sign-in?reset=1` | 로그인 화면 상단(대표 결정 5 반영) | 비밀번호가 변경됐어요. 새 비밀번호로 로그인해 주세요. 다른 기기에서는 다시 로그인해야 해요. |

- RP-NOTOKEN-DESC는 기존 "링크가 올바르지 않아요. 재설정 이메일을 다시 요청해 주세요."에서 "재설정 이메일"을 쉬운 말로 바꾸고, 링크가 메일 앱에서 잘려 열린 경우(6.2) 먼저 해 볼 일을 한 가지 더했다.
- RP-EXPIRED-ERR의 "실패했어요"를 "바꾸지 못했어요"로 바꿨다. 사용자를 탓하지 않고 결과만 말한다. 원인은 추측("~수 있어요")으로 쓴다. 토큰 없음과 만료를 서버가 구분하지 않기 때문이다.
- 만료 화면에서 입력한 비밀번호는 지우지 않는다. RP-RESEND-BTN은 이 알림 바로 아래에 둔다.
- 대표 결정 5(login-fail 해제)로 성공 배너에 "로그인이 막히면 15분 뒤에" 안내는 넣지 않는다.
- 성공 배너를 열 때 가입 마무리 전이던 회원이 헷갈리지 않도록 별도 문구를 두지 않는다(정의서 3장).
- RP-NOTICE 옵션

| 옵션 | 문구 | 뉘앙스 |
|---|---|---|
| A (권장) | 새 비밀번호를 정해 주세요. 변경하면 모든 기기에서 로그아웃돼요. | 할 일 다음에 결과를 알려 준다. |
| B | 비밀번호를 바꾸면 지금 로그인한 모든 기기에서 로그아웃돼요. | 이유가 길고 "지금 로그인한"이 필요 없는 설명이다. |
| C | 변경 후 다른 기기에서는 다시 로그인해야 해요. | 부드럽지만 "모든 기기"라는 사실이 약해진다. 성공 배너와 같은 표현이라 중복이다. |

## 5. 메일 문구

메일 템플릿은 `api/src/mail/ses.ts`의 구조(인사 → `intro` → 링크 → `after` → 문의처 → `closing` → 서명)를 그대로 쓴다. 인사("안녕하세요. 바라 평생교육원이에요.")·문의처(전화·운영시간)·서명("바라 평생교육원")은 자동으로 붙으므로 `intro`·`after`·`closing`에 넣지 않는다. 전화번호는 `SUPPORT_PHONE`, 운영시간은 `SUPPORT_HOURS`를 쓴다. 다른 템플릿(profile_changed, already_registered)도 문의처를 같은 방식으로 붙인다.

### 5.1 `password_changed` 알림 메일 (신규, 대표 결정 3)

- 링크 없음. 새 비밀번호나 이전 비밀번호를 메일에 적지 않는다.
- `{at}`는 변경 시각이다. `profile_changed`와 같은 방식으로 채운다(`{at}` 형식을 그 메일과 맞춘다).
- 받는 사람은 재설정이 끝난 회원의 가입 이메일이다.

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| MAIL-CHANGED-SUBJECT | 제목 | [바라 평생교육원] 비밀번호가 바뀌었어요 |
| MAIL-CHANGED-INTRO-1 | `intro` 1 | 회원님의 비밀번호가 바뀌어서 알려 드려요. |
| MAIL-CHANGED-INTRO-2 | `intro` 2 | 바뀐 시각: {at} |
| MAIL-CHANGED-INTRO-3 | `intro` 3 | 보안을 위해 모든 기기에서 로그아웃했어요. 새 비밀번호로 다시 로그인해 주세요. |
| MAIL-CHANGED-INTRO-4 | `intro` 4 | 회원님이 직접 바꾼 것이 맞다면 따로 하실 일은 없어요. |
| MAIL-CHANGED-AFTER | `after`(문의처 앞) | 본인이 바꾸지 않았다면 바로 전화로 알려 주세요. |

완성된 모양

```
안녕하세요. 바라 평생교육원이에요.

회원님의 비밀번호가 바뀌어서 알려 드려요.
바뀐 시각: {at}
보안을 위해 모든 기기에서 로그아웃했어요. 새 비밀번호로 다시 로그인해 주세요.
회원님이 직접 바꾼 것이 맞다면 따로 하실 일은 없어요.

본인이 바꾸지 않았다면 바로 전화로 알려 주세요.

전화: {SUPPORT_PHONE}
운영시간: {SUPPORT_HOURS}

바라 평생교육원
```

- 문구 구조는 `profile_changed`(회원 정보가 바뀌었어요)와 맞췄다. 같은 종류의 알림이라 같은 순서(알림 → 시각 → 맞다면 할 일 없음 → 아니라면 전화)를 쓴다.
- 전화 안내는 번호를 본문에 적지 않고 템플릿의 문의처 블록에 맡긴다. 번호를 새로 만들지 않는다.
- 링크를 넣지 않는 이유: 이 메일을 본 사람이 링크로 비밀번호를 다시 바꾸게 하면 가짜 메일(피싱)과 구분이 안 된다. 전화로만 연결한다.
- "계정이 해킹됐다" 같은 겁주는 말은 쓰지 않는다. 시니어가 놀라지 않게 사실(바뀜 + 로그아웃)과 할 일(아니면 전화)만 말한다.
- MAIL-CHANGED-SUBJECT 옵션

| 옵션 | 제목 | 뉘앙스 |
|---|---|---|
| A (권장) | [바라 평생교육원] 비밀번호가 바뀌었어요 | 결과를 그대로 말한다. 회원 정보 알림과 같은 문형. |
| B | [바라 평생교육원] 비밀번호 변경 안내 | 기존 "재설정 안내"와 짝이 된다. 사실만 있어 눈에 덜 띈다. |
| C | [바라 평생교육원] 비밀번호 변경을 확인해 주세요 | 확인할 일이 있는 것처럼 보여 피싱 메일과 비슷해진다. 비권장. |

### 5.2 `recovery` 메일 보완 (기존 템플릿)

현재 `intro`: "아래 링크에서 새 비밀번호를 설정해 주세요. 링크는 1시간 동안 유효해요. 요청하지 않았다면 이 메일을 무시해 주세요."

변경: `intro`는 쉬운 말로 다듬고, `after`를 추가한다. 제목은 그대로 둔다("[바라 평생교육원] 비밀번호 재설정 안내").

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| MAIL-RECOVERY-SUBJECT | 제목(유지) | [바라 평생교육원] 비밀번호 재설정 안내 |
| MAIL-RECOVERY-INTRO-1 | `intro` 1(변경) | 아래 링크를 열고, 새 비밀번호를 정해 주세요. 링크는 1시간 동안 쓸 수 있고, 한 번만 쓸 수 있어요. |
| MAIL-RECOVERY-INTRO-2 | `intro` 2(변경) | 본인이 요청하지 않았다면 이 메일을 무시해 주세요. 아무것도 바뀌지 않아요. |
| MAIL-RECOVERY-AFTER-1 | `after` 1(추가) | 링크가 열리지 않으면 주소를 복사해 인터넷 창에 붙여 넣어 주세요. |
| MAIL-RECOVERY-AFTER-2 | `after` 2(추가) | 비밀번호를 바꾸면 모든 기기에서 로그아웃돼요. |

- "한 번만 쓸 수 있어요"와 "링크가 열리지 않으면" 문장은 가입 인증 메일(`confirm`)의 말과 같게 썼다.
- "유효해요"를 "쓸 수 있어요"로 바꿨다. 가입 인증 메일과 단어를 통일하고, 한자어를 줄인다.
- "아무것도 바뀌지 않아요"는 `confirm`·`already_registered` 메일에서 쓰는 같은 문장이다.
- 새 문장은 `after`(링크 뒤)에 둔다. 링크 앞이 길어지면 핵심 할 일(링크 열기)이 묻힌다.
- 같은 템플릿을 관리자 [비밀번호 재설정 메일 발송]도 쓴다. 문구가 셀프 요청과 관리자 발송 모두에 맞다.

### 5.3 `already_registered` 메일 보완 (기존 템플릿)

현재 `after`: "비밀번호가 기억나지 않으면 전화로 문의해 주세요. 확인 후 재설정 메일을 보내 드려요."

변경: 셀프 경로를 앞에 두고 전화는 그 뒤에 둔다(대표 결정으로 전화 응대는 보조 경로가 된다).

| 슬롯 ID | 위치 | 문구 |
|---|---|---|
| MAIL-REG-AFTER-1 | `after` 1(변경) | 비밀번호가 기억나지 않으면 아래 주소에서 새로 정할 수 있어요. |
| MAIL-REG-AFTER-2 | `after` 2(추가, 주소 한 줄) | {origin}/forgot-password |
| MAIL-REG-AFTER-3 | `after` 3(변경) | 주소가 열리지 않거나 어려우면 전화로 문의해 주세요. |

- 이 메일에는 이미 `link`(로그인 주소)가 있다. 비밀번호 찾기 주소는 `link`와 별개라 본문 줄로 넣는다. `{origin}`을 채우려면 `fill`이 `{origin}`을 지원하거나 `intro`·`after`에 완성된 주소를 넘겨야 한다(backend-developer에게 전달).
- 나머지 문구(제목 "이미 가입된 이메일이에요", `intro`, `closing`)는 바꾸지 않는다. 이 메일은 이미 열거 방지로 가입 시도 시에만 가는 메일이다. 여기서 새로 드러나는 정보는 없다.
- 전화 문구에서 "확인 후 재설정 메일을 보내 드려요"를 뺐다. 이제 먼저 할 일이 셀프 요청이라 약속이 두 갈래로 읽히지 않게 한다. 전화로 연결되면 운영자가 응대 스크립트(가입 인증 문서 6장)로 처리한다.

## 6. 확인이 필요한 것

- 5.3의 `{origin}`: `already_registered` 메일에서 주소를 어떻게 채울지는 backend-developer가 정한다. 코드에서 이 주소를 만들 수 없다면 `link` 필드 대신 `after` 줄에 완성된 주소를 넘기는 방법이 있다.
- 5.1의 `{at}` 형식은 `profile_changed` 메일과 같은 형식이어야 한다. 시각 형식이 다르면 두 메일이 어색해진다.
- FP-ERR-429·FP-ERR-UNAVAILABLE·RP-ERR-UNAVAILABLE의 "입력한 내용은 그대로예요"는 실제로 입력값을 유지하는 구현에서만 쓴다. 유지하지 않으면 이 문장을 뺀다.
- EP-FINISH-FORGOT-BODY·EP-LOCKED-GUIDE는 가입 마무리 문서(`signup-verify-password-copy.md`) 4.3·4.4·4.5장의 문구를 대체한다. 두 문서가 어긋나지 않게 다음 문서 동기화 때 그 문서의 4.3~4.5장과 6장(전화 응대, 셀프 경로 안내 우선)을 함께 고친다.
- `signup-enumeration-copy.md` 3장 `already_registered` 메일의 비밀번호 문의 문구도 5.3과 맞춰 고친다.
- 메일 문구 변경은 `api/test`의 메일 본문 테스트를 갱신해야 한다(qa-reviewer).
