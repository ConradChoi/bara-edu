## 2. 지금 상태 (운영 DB 읽기 전용 확인, 2026-11-27 16시)

- `legal_documents`
  - privacy: v1~v10이 있다. 한 번이라도 게시된 버전(`published_at` 있음)은 v1~v4, v7~v10이고, 공개 화면의 버전 선택 목록에 지금도 나온다. 현재 게시본은 v10(11-26 22:24)이다.
  - terms: v1(08-06 게시).
  - refund-policy: v1(09-16 게시).
- 본문의 날짜와 버전 표기
  - privacy: 끝부분에 "변경 사유 및 고지 안내: 이번 개정(v10)은 …" 문단이 있고, `공고일자 2026년 11월 26일 / 시행일자 2026년 11월 26일 / 버전: v10`이 적혀 있다.
  - terms: "부칙 … 본 약관은 2026년 8월 6일부터 시행합니다."와 `버전: v1`이 적혀 있다.
  - refund-policy: `공고일자·시행일자 2026년 9월 16일 / 버전: v1`이 적혀 있다.
- `diagnosis_results` 2건의 `consent_privacy_doc_version`이 10이다. 민감정보 동의 문구 버전 `sc-v1`은 따로 관리하며 바꾸지 않는다.
- 새 버전 번호는 `createNewVersion`이 같은 slug의 가장 큰 번호 + 1로 매긴다. v10 행이 남아 있으면 다음 개정이 v11이 된다.

## 2-1. 개인정보 점검 결과와 추가 결정 (2026-11-27)

- 개인정보 점검 판정은 조건부 Go(치명 없음)다. 조건인 주요 5건은 아래 3장에 모두 반영했다.
- 추가 대표 결정
  - **실제 이용자가 있다.** 그래서 오픈 전 원문을 보관하고, 동의 기록은 v10을 유지하고, 회원 안내 메일을 보내고, 처리방침에 "오픈 전 방침은 요청 시 제공"을 넣는다.
  - **사전신청 이메일은 안내 없이 파기한다.**
- 처음 계획에서 바꾼 것
  - privacy v10 행을 제자리에서 고치지 않고 **보관 후 삭제한다.** 그리고 새 행(version 1)을 넣는다.
  - 동의 기록 10→1 변경은 **하지 않는다.**
  - terms·refund-policy도 원본을 먼저 보관한다.

## 3. 할 일

### 3.1 앱 (코드, QA 대상)

- `lib/legal-version.ts`에 두 함수를 둔다.
  - `formatDocVersion(n)`: `v{n}.0`을 돌려준다.
  - `formatConsentPrivacyDoc(n, consentedAt)`: 버전 10이면서 2026-11-28 0시(KST) 전에 동의한 기록은 `오픈 전 v10`으로 보인다. 오픈 전 동의 기록은 모두 v10이다.
- 버전 표기를 바꾸는 화면
  - 공개 버전 선택
  - CMS 목록과 편집(세 군데)
  - 관리자 자가진단 상세(SC-ADM-CONSENT-VALUE `{doc}`)
- `components/home/ComingSoon.tsx`에서 사전신청 폼과 전송 코드를 뺀다. 이 화면은 오픈 상태를 되돌릴 때만 보인다.

### 3.2 DB (실행 직전 대표 확인)

1. 패치 `api/db/patches/2026-11-27-legal-prelaunch-archive.sql`을 적용한다.
   - `archive` 스키마(웹 역할에 usage 없음)와 `archive.legal_documents_prelaunch`를 만든다.
   - 멱등이고 데이터는 바꾸지 않는다.
2. 1회용 스크립트 `api/db/oneoff/2026-11-27-launch-v1.cjs`를 실행한다. 기본은 확인만 하고 되돌리며, `--execute`일 때 반영한다. 한 트랜잭션 안에서 아래를 한다.
   - 기대 건수를 확인한다. 다르면 롤백한다.
   - `legal_documents` 12행 전부를 원래 값 그대로 보관 테이블에 복사한다.
   - 수료증 1건과 문의 1건을 지운다. 행마다 접속 기록을 1건 남긴다: action `오픈전정리삭제`, detail `by=db;operator=개발;reason=launch_cleanup;table=…;id=…;fields=row`, admin_id는 대표 관리자. 이름·연락처는 넣지 않는다.
   - privacy 10행을 지운다. 그다음 v1.0 본문(`docs/legal/v1.0/privacy.txt`)을 version 1로 넣고 게시한다. published·effective는 지금이다.
   - terms·refund-policy의 본문(시행일·버전 표기)과 published·effective를 지금으로 바꾼다.
   - 자가진단 결과의 `consent_privacy_doc_version`(10)은 바꾸지 않는다.
3. 원문 내보내기 파일 `docs/legal/prelaunch-archive/legal-documents-prelaunch-2026-11-27.json`과 sha256을 저장소에 보관한다. 개인정보가 없는 공개 문서다.
   - 보관 기간은 해당 시기 가입 계정이 남아 있는 동안 + 탈퇴 후 3년이다. 근거는 변호사 검토 대상이다.

### 3.3 v1.0 본문 (`docs/legal/v1.0/`, 원문 대비 바뀐 곳만)

- privacy
  - 내부 표현 두 줄을 다듬는다("최초의 경로입니다" 문장 삭제, "Phase 1은 …"을 "진단 결과를 문자·메일로 보내지 않으므로 … 연락 수단 1개만 받습니다(최소 수집)"로).
  - "변경 사유 및 고지 안내(v10)" 문단을 빼고 제11조 (3)을 넣는다: "정식 오픈(2026년 11월 27일) 전에 게시했던 개인정보처리방침은 제9조의 연락처로 요청하시면 제공해 드립니다."
  - 공고일자·시행일자는 2026년 11월 27일, `버전: v1.0`이다.
  - 제5조 SES 위탁 업무에 "서비스 이용 관련 고지(약관·개인정보처리방침 변경 안내 등)"를 더한다. 오픈 안내 메일이 SES로 나가기 때문이다(재점검 C1).
- terms: 부칙 시행일을 2026년 11월 27일로, `버전: v1.0`으로 바꾼다. 제1조의 서비스 주소 오기(`https://ylia.io`)를 `https://bara-edu.kr`로 바로잡는다(대표 결정 11-27, 회원에게 불리하지 않은 오기 정정).
- refund-policy: 공고일자·시행일자를 2026년 11월 27일로, `버전: v1.0`으로 바꾼다.
- CMS 실제 본문에는 변경 이력 표나 `(준비본)` 표기가 없다(11-27 확인). 저장소 준비본과 다르다.

### 3.4 사전신청 이메일 파기 (대표 결정: 안내 없이 파기)

- 코드: 폼과 전송을 제거한다(3.1).
- Amplify 앱 환경 변수 `NEXT_PUBLIC_APPS_SCRIPT_URL`을 삭제하고 다시 빌드한다(공용 설정, 대표 확인).
- 대표가 할 일(Google 계정)
  - Apps Script 웹 앱 배포를 해제한다.
  - 시트의 건수를 확인한 뒤 스프레드시트 파일을 삭제하고 Drive 휴지통을 비운다.
  - 운영 기록에는 일시·건수·방법만 남기고 주소는 남기지 않는다.

### 3.5 회원 안내 메일 1회 (`api/db/oneoff/2026-11-27-launch-notice-mail.cjs`)

- 활성 학습자(5명)에게 한 명씩 따로 보낸다. 광고가 아닌 처리방침·약관 게시 안내다.
- 기본은 받을 사람 수만 출력하고, `--send`일 때 보낸다.
- 문구는 스크립트 안의 `TEXT`이다. 대표가 11-27에 승인했다.
  - 제목은 "개인정보처리방침·이용약관 게시 안내"이다. 광고로 읽히지 않게 사실 고지로 쓰고, 강좌나 혜택 문구는 넣지 않는다(재점검).
  - `--send`에는 `--expect=<n>`이 함께 있어야 한다. 받는 사람 수가 n과 다르면 보내지 않는다.
  - 발송 일시와 건수(주소 없음)를 운영 기록에 남기고 다시 보내지 않는다.
- 문서 정리 스크립트는 **2026-11-28 0시(KST) 전에** 실행한다. 화면의 "오픈 전 v10" 판정 기준 시각이기 때문이다(재점검 C3). 실행 뒤에는 동의 기록 v10이 2건 그대로인지 확인한다.

### 3.7 남는 것

- 수료증: 학습자가 수료 조건을 모두 채웠다면 수료증을 다시 신청해 받을 수 있다. 지운 것은 지금 발급된 행뿐이다.
- 이전 안내 팝업: 11/30까지 그대로다(D4). 팝업에 오픈 안내 한 줄을 더하는 권고는 대표 결정에 따라 하지 않는다.
- 후속 개정 안건
  - 동의 기록에 문서 행 id 스냅샷을 추가한다.
- L8(당일 시행): 개인정보 점검이 변호사 재질의를 권고했으나, 대표가 11-27에 다시 묻지 않기로 결정했다.

## 4. 점검 쟁점 결론

1. 준비 버전: 삭제하지 않고 비노출 보관 테이블과 내보내기 파일로 보관한다.
2. 동의 기록: 10을 유지하고, 화면은 "오픈 전 v10"으로 보인다.
3. 삭제 기록: 3.2의 형식을 따른다. `삭제요구처리`는 쓰지 않는다(월간 점검과 겹치지 않게).
4. 당일 시행: 대표 결정으로 재질의하지 않는다(3.7).
