## 0. 원칙

- 정상 케이스만 적지 않는다 — 모든 플로우에 실패/예외 케이스를 붙인다.
- 애매한 정책(입금 기한, 수료 기준 등)은 임의로 정하지 않고 6절에 열린 질문으로 남긴다. 단, 논의 속도를 위해 각 질문에 **권장안**은 제시한다.

## 2. USER 플로우

### 2.1 회원가입 / 로그인

```
[비로그인] → 회원가입 클릭 → 이름/이메일/비밀번호/연락처 입력 → 가입 완료
                                                          → (이메일 인증? [확인필요 Q1])
[비로그인] → 로그인 클릭 → 이메일/비밀번호 입력 → 마이페이지 이동
```

| 상태 | 화면 표시 |
|---|---|
| 입력 중 | 실시간 검증 없음(blur 시 검증 — 유효성 검사 패턴) |
| 제출 중 | 버튼 로딩, 중복 클릭 방지 |
| 실패: 이메일 중복 | "이미 가입된 이메일이에요. 로그인해 주세요" + 로그인 링크 |
| 실패: 비밀번호 정책 미달 | 조건을 구체적으로 안내(예: 8자 이상) |
| 실패: 로그인 정보 불일치 | "이메일 또는 비밀번호가 올바르지 않아요" (어느 쪽이 틀렸는지는 특정하지 않음 — 보안) |

**엣지케이스**: 세션 만료 중 마이페이지/강의실 접근 → 로그인 화면으로 리다이렉트 후 원래 목적지로 복귀.

### 2.2 강좌 탐색 → 신청 → 무통장입금

```
강좌 목록 → 강좌 상세 → [수강 신청하기]
  ├─ 비로그인 → 로그인/가입 유도 → 로그인 후 신청 화면으로 복귀
  └─ 로그인 상태 → 신청 확인(강좌명/기간/수강료) → 입금 안내(계좌/입금자명/기한)
       → enrollments.status='pending' 생성 → 마이페이지에 "입금 대기" 노출
       → (Admin 승인) → status='approved' → 강의실 접근 권한 부여 + 알림
```

| 화면 | 구성요소 | 동작 | 예외처리 |
|---|---|---|---|
| 강좌 상세 | 신청 버튼, 정원 표시 | 클릭 시 신청 확인 화면 | 정원 마감 시 버튼 비활성화 + "정원이 마감되었어요" |
| 신청 확인 | 강좌 요약, 수강료, 동의 체크 | [신청 확정] | 이미 신청/수강 중인 강좌 재신청 시도 → 안내 후 마이페이지로 유도 |
| 입금 안내 | 계좌번호, 입금자명 안내, 입금 기한, 복사 버튼 | 안내만, 실제 입금은 사용자가 외부에서 수행 | 입금 기한 초과 → [확인필요 Q2] |

**엣지케이스**: 같은 강좌에 중복 신청 시도 → 차단. 입금 대기 중 강좌 정원이 다른 신청으로 마감됨 → 승인 시점에 Admin에게 경고 표시(선착순 정책은 Q3).

### 2.3 강의실 학습 (진도)

```
마이페이지 → 내 강좌 → [강의실 입장] (approved 상태만 접근 가능)
  → 커리큘럼 목록(강의 1..N) → 강의 선택 → 영상(외부 링크 임베드) 시청
  → [학습 완료로 표시] → progress 기록 → 진도율 갱신
```

| 상태 | 화면 표시 |
|---|---|
| 미승인(pending) 상태에서 강의실 접근 시도 | "입금 확인 후 이용 가능해요" + 마이페이지 링크 |
| 진도 0% | 첫 강의부터 시작 안내 |
| 진도 100% | 수료 조건 확인 후 수료증 발급 유도 |

**엣지케이스/열린 질문**: 강의 순서를 강제할지(순차 수강) 여부는 Q4. 완료 체크는 "링크 클릭 시 자동 완료"가 아니라 **사용자가 직접 [학습 완료로 표시]를 눌러야 기록**하는 것을 기본값으로 제안(영상은 외부 링크라 재생 완료를 시스템이 감지할 수 없음).

### 2.4 퀴즈 / 과제

```
강의실 내 특정 강의 또는 챕터에 [퀴즈] 또는 [과제] 배치
퀴즈: 객관식 문항 응답 → 제출 → 즉시 채점 → 점수/합격 여부 표시
과제: 텍스트 또는 링크 제출 → Admin 검토 대기 → 승인/반려
```

| 예외 | 처리 |
|---|---|
| 퀴즈 재응시 | 허용 여부/횟수는 Q5 |
| 과제 마감 기한 초과 제출 | 제출은 허용하되 "기한 초과" 배지 표시(정책은 Q6) |
| 과제 반려 | 반려 사유와 함께 재제출 유도 |

### 2.5 수료증 발급

```
진도율 100% (+퀴즈/과제 통과 조건 충족 시 — 기준은 Q7) → [수료증 발급받기] 버튼 활성화
→ 클릭 시 PDF/이미지 생성 → 다운로드 + 마이페이지에 보관
```

**엣지케이스**: 조건 미충족 상태에서 버튼은 비활성화 + 부족한 항목을 명시("과제 제출 후 발급 가능해요"). 재발급 요청은 마이페이지에서 재다운로드로 처리(별도 승인 불필요).

### 2.6 마이페이지 구성

신청 내역(상태: 대기/승인/반려) · 수강 중인 강좌(진도율) · 완료한 강좌 · 수료증 목록 · 계정 정보 수정 · **설정(회원 탈퇴)**.

### 2.7 회원 탈퇴 (Q10~Q12)

```
마이페이지 → 설정 → [회원 탈퇴]
  → 진행 중(입금대기/수강중) 강좌 존재? ─ Yes → 탈퇴 차단 + 안내("진행 중인 강좌가 있어 탈퇴할 수 없어요")
                                    └ No  → 탈퇴 확인 다이얼로그(결과 설명: 계정 비활성화, 재가입은 가능)
                                              → [탈퇴하기] → profiles.status='withdrawn' + 이름/연락처 익명화
                                              → Supabase Auth 세션 종료 → 홈으로 이동
```

**엣지케이스**: 탈퇴 확인 다이얼로그는 "확인·경고 다이얼로그" 패턴(파괴적 액션이므로 확정 문구 필요, 단순 "확인"이 아니라 "탈퇴하기"). 탈퇴된 계정으로 재로그인 시도 → "탈퇴한 계정이에요" 안내(재가입은 허용되므로 로그인이 아니라 회원가입으로 유도).

## 3. Admin 플로우

### 3.1 로그인 / 권한

Admin 전용 로그인 경로. `profiles.role='admin'`이 아닌 계정은 Admin 라우트 접근 시 403 + 홈으로 리다이렉트. 최초 Admin 계정 생성 방식은 [확인필요 Q8](수동 DB 등록 vs 초대 코드).

### 3.2 대시보드

신규 신청 수 · 입금 대기 건수 · 오늘 승인 처리 건수 · 수료 임박 학습자 수를 카드로 요약, 각 카드 클릭 시 해당 목록으로 이동(테이블 전체보기·더보기 패턴).

### 3.3 강좌 관리 (CRUD)

목록(테이블) → [신규 등록] / 행 클릭 시 상세·수정. 커리큘럼(강의) 항목은 강좌 상세 내 서브 목록으로 추가/삭제/순서 변경. 강의 등록 시 영상 링크 URL 형식 검증(파일 업로드 아님).

| 예외 | 처리 |
|---|---|
| 신청자가 있는 강좌를 status='closed'로 변경 | 확인 다이얼로그("이미 신청 N건이 있어요, 계속할까요?") |
| 강좌 삭제 시도(신청 이력 존재) | 삭제 대신 비활성화만 허용 — 이력 보존 |

### 3.4 회원 관리

학습자 목록(테이블, 검색/필터) → 상세(신청 내역, 진도, 수료증 이력). 회원 정보 직접 수정은 최소화(연락처 등 운영상 필요한 항목만).

### 3.5 신청 · 입금 관리 (핵심 화면)

```
입금 대기 목록(테이블, 상태='pending') → 행 선택 → 입금 확인(운영자가 실제 계좌 대사) → [승인] 또는 [반려]
[승인] → status='approved' → 학습자에게 알림(이메일/화면) → 강의실 접근 즉시 부여
[반려] → 반려 사유 입력 필수 → status='rejected' → 학습자에게 사유와 함께 알림
```

| 엣지케이스 | 처리 |
|---|---|
| 여러 운영자가 동시에 같은 신청을 처리 시도 | 먼저 처리된 쪽이 확정, 나중 처리자에게는 "이미 처리됨" 안내 (동시성) |
| 승인 후 정원 초과 발견 | 승인은 막지 않되(운영자 재량), 대시보드에 경고 표시 |
| 장기 미입금(기한 초과) | 자동 만료 처리 여부는 Q2와 연동해 결정 |
| 잘못 승인 후 취소 필요 | 승인 취소 액션 제공, 파괴적 액션이므로 확인 다이얼로그 필수 |

### 3.6 진도 / 수료 관리

수료 조건 충족 학습자 목록 → 수료증 발급 상태 확인. 수동으로 예외 수료 처리(예: 오프라인 보강 인정)가 필요한지는 Q9.

## 4. 화면 정의서 요약

| 화면 | 핵심 구성요소 | 참고 UX 패턴(YLIA 가이드) |
|---|---|---|
| 회원가입/로그인 | 폼, 검증 메시지 | 폼 기본 구조, 유효성 검사 |
| 강좌 신청/입금 안내 | 요약 카드, 안내 텍스트 | 상세 화면 기본 구조, 확인 다이얼로그 |
| 마이페이지 | 탭/섹션(신청내역/진도/수료증) | 상세 화면 기본 구조, 목록 테이블 |
| 강의실 | 커리큘럼 목록 + 영상 임베드 + 완료 체크 | 단계형 입력 위저드(진행 표시 개념 차용) |
| 퀴즈 | 문항/선택지/제출 | 폼 기본 구조 |
| 과제 제출 | 텍스트/링크 입력, 첨부(선택) | 파일 업로드, 저장·임시저장 |
| Admin 대시보드 | 요약 카드 4종 | 테이블 전체보기·더보기 |
| Admin 강좌 관리 | 목록 테이블 + 등록/수정 폼 | 목록 테이블 기본 동작, 폼 기본 구조 |
| Admin 신청·입금 관리 | 목록 테이블 + 상세 패널 + 승인/반려 액션 | 목록 테이블, 확인·경고 다이얼로그, 토스트 |

## 5. 엣지케이스 종합표

| 영역 | 케이스 | 우선순위 | Figma 와이어프레임 |
|---|---|---|:---:|
| 인증 | 세션 만료 중 보호 페이지 접근 | 필수 | ✅ 01c |
| 신청 | 중복 신청 | 필수 | ☐ (서버 재검증, 별도 화면 불필요 — 토스트/안내만) |
| 신청 | 정원 마감 중 신청 | 필수 | ✅ 02-full (Button Disabled) |
| 입금 | 장기 미입금(기한 만료) | 필수 | ✅ 03 신청내역-만료 카드 |
| 입금 | 동시 승인 처리 충돌 | 필수 | ✅ 06 하단 Toast 주석 |
| 강의실 | 미승인 상태 접근 | 필수 | ✅ 04d |
| 강의실 | 강좌 비활성화 후 접근 | 필수 | ☐ (04d와 동일 패턴 재사용 예정, 카피만 다름) |
| 퀴즈/과제 | 재응시/재제출, 마감 초과 | 중요 | ☐ (기한초과 배지는 04c에 이미 반영, 재응시는 별도 화면 불필요) |
| 수료증 | 조건 미충족 발급 시도, 재발급 | 중요 | ☐ |
| Admin | 신청 이력 있는 강좌 삭제 시도 | 필수 | ✅ 07 하단 ConfirmDialog 주석 |
| Admin | 승인 취소 | 필수 | ☐ (ConfirmDialog Danger 재사용 예정, 별도 와이어프레임 불필요) |
| 강좌 목록 | 빈 상태(강좌 0개) | — | ✅ 02a-empty |
| 공통 | 잘못된 경로(404) | — | ✅ 신규 "12 404 페이지" |

> "☐" 항목은 기존 컴포넌트(Button Disabled, ConfirmDialog, Badge 등) 재사용으로 충분해 별도 화면을 만들지 않았거나, 우선순위가 낮아 후속 작업으로 남긴 것 — 구현 누락이 아니다.

## 6. 확정된 정책 (2026-08-01 product-manager 승인)

| # | 질문 | 확정 정책 |
|---|---|---|
| Q1 | 회원가입 이메일 인증 필수 여부 | 1차는 생략(가입 마찰 최소화), 어뷰징 발생 시 추가 |
| Q2 | 무통장입금 기한 / 미입금 처리 | 입금 기한 3일, 초과 시 자동 만료(재신청 가능) |
| Q3 | 정원 마감 판단 시점 | 입금 승인 시점 기준(입금 대기 중 취소 가능성 고려) |
| Q4 | 강의 순차 수강 강제 여부 | 강제하지 않음(자유 수강) |
| Q5 | 퀴즈 재응시 허용 횟수 | 무제한 허용 |
| Q6 | 과제 마감 초과 제출 허용 여부 | 허용, "기한 초과" 표시만 (감점 없음) |
| Q7 | 수료 기준 | 진도율 100% + (과제가 있는 강좌는) 과제 승인 완료 |
| Q8 | 최초 Admin 계정 생성 방식 | 개발 단계에서 Supabase 콘솔로 수동 등록(초대 시스템은 2차) |
| Q9 | 예외적 수료 인정(오프라인 보강 등) | Admin이 수동으로 수료 처리할 수 있는 버튼 제공 |
| Q10 | 회원 탈퇴 시 개인정보 처리 | 소프트 삭제 + 이름/연락처 즉시 익명화. 거래·결제 관련 기록은 법정기간 보관 후 파기 (정확한 보관기간은 security-officer가 전자상거래법 등 검토 후 확정) |
| Q11 | 탈퇴 후 재가입 허용 여부 | 허용 (같은 이메일로 재가입 가능) |
| Q12 | 진행 중(입금대기/수강중) 강좌가 있을 때 탈퇴 처리 | 탈퇴를 막고 안내 (환불·정산 문제 방지 — "진행 중인 강좌가 있어 탈퇴할 수 없어요. 고객센터로 문의해 주세요") |

이 정책들은 화면 정의서(4절)와 엣지케이스(5절)에 이미 반영되어 있으며, ui-ux-designer는 이 문서를 그대로 Figma 설계 입력으로 사용한다.

> Q10의 정확한 법정 보관기간은 **security-officer가 반드시 재검토**해야 하는 항목이다 — 임의로 "5년" 등을 확정값으로 쓰지 않는다.
